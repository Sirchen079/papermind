# 回答转为本地研究文档

2026-09-26，开发源码。解决 [FWI 纠正与接续](fwi-correction-continuation.md) 中实际遇到的断点：有价值的普通回答只能复制或另存论文笔记，成为可编辑研究文档还要请求模型调用 `save_document`。

## 产品取舍

研究者读到有用回答后，应能立即留下来、修改、继续使用。保存是本地应用的工作，无需再次让模型生成内容，也不要求先关联某一篇论文。这一步减少复制粘贴、重新解释上下文和单纯为保存而等待模型的操作。

回答下方新增“保存为文档”。点击后原样保存正文与已有来源，并直接打开现有编辑器。可以关闭，也可以保存修改后的新版本；原回答与原文件保留。再次点击显示“查看已存文档”，能从原版本进入后续修订。新对话通过“已保存文档”查找并引用确切版本，刷新后仍可接续。

保存本身不代表研究者确认了回答中的结论。目录明确显示“从 AI 回答保存”，后续编辑才标记为人工修订；API 保留原模型、回答状态和原消息编号。非空的中断回答也可以保存，不要求先完成整份回答或通过质量检查。

## 先查现成机制，再补缺口

[OpenCode TUI](https://opencode.ai/docs/tui/) 已提供 `/export`，可将会话导出为 Markdown 并在编辑器中打开。本项目借鉴本地导出后继续编辑的交互，不复制外部代码。

仓库已具备 Markdown 导出、来源快照、文档目录、版本关系、编辑器、跨对话附件和 agent 回读工具。本次复用它们，只增加从一条持久化回答发起保存的入口；没有新建文档服务或迁移数据库。

- 后端从当前研究空间、指定对话中的原消息读取正文；不接受客户端重传原文与来源。
- 新增本地保存记录，关联原回答；不修改原回答，也不伪造模型工具调用。重复保存同一条回答返回已有记录。
- 首次保存是文档起点；之后编辑复用现有父版本关系、原稿保留及新版本发现。
- 后续同对话上下文保留原回答一次，另携带保存记录及 `read_saved_document` 入口，避免因保存而重复发送整段正文。已有人工修订仍按原机制进入上下文。
- 论文与网页来源延用现有快照机制。研究稿正文不会被当成论文原文证据。

## 验证与边界

隔离环境复制上一轮真实 GLM 的 FWI 回答（对话 8、消息 29），移除测试副本的模型密钥并停用提供商。CUA 界面验证完成：保存后打开编辑器、添加明确标识的验收补记、另存新版本、刷新后从回答找回文档、由原版进入修订版、新对话加入修订稿，以及刷新后保留确切版本引用。

原消息所有数据库字段保持不变；正文和来源保留；原文件和修订文件同时存在。界面操作未请求模型，模型调用监测为 0。跨对话发送并回读正文、来源由后端模拟模型测试覆盖，本轮没有新调用外部模型生成科研结论。

59 项相关后端测试通过，覆盖原样保存、重复请求、非空中断回答、保存失败后重试、研究空间隔离、论文及网页来源、修改和跨对话回读、失败任务接续、原回答身份、后续上下文不重复，以及现有文档功能回归。141 项前端测试与 TypeScript/Vite 生产构建通过。运行证据记录于工作区 `answer-document-capture-20260926/validation.json`。

本次实现随后与 [阅读空间调整](chat-reading-space.md) 一起纳入 [0.6.14 桌面候选](release-0.6.14-validation.md)，安装包提取程序中的保存、修改、重启找回及新对话引用通过；0.6.13 交付保留。它补齐了成果保存和接续的一步，不能据此宣称模型内容正确、数值 FWI 已验证，或真实研究者总工作量已经大幅减少。

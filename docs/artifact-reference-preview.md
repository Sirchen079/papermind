# 成果引用的可读预览

2026-09-26，开发源码完成。已交付 0.6.14 安装包保持不变，本项尚未重新打包。

## 用户任务与复用

研究者在继续讨论前，需要确认交给 AI 的是哪份稿、哪一版、哪段选文，以及有哪些来源。0.6.14 的附件展开显示 `message_id`、`read_saved_document` 等模型指令，用户仍需离开对话寻找正文。

检查现有实现后，复用 SavedDocuments、文档详情接口、研究任务的完整版本历史、专题综述及逐篇来源接口、Markdown 和网页摘录组件。已有接口足以完成读取，没有新增后端、成果存储、模型请求或审批流程，也没有复制外部代码。专题综述原有请求函数与类型提取为共享模块，原页面继续使用同一接口。

## 行为

- 文档引用打开正文、保存时间、所属对话、保存或修订类型及来源。原稿存在后续修订时说明关系，仍展示被引用的版本；可进入已有文档窗口查看修订、选择段落或重新关联。
- 本轮待核查选文单独显示，包括历史附件中已保存的选文；读取失败时也保留它。给模型的附件文字及结构化引用不变。
- 论文研究按引用版本同时读取判断与当时的来源快照。找不到该版本时显示重试入口，不用最新版冒充；该错误不阻断对话发送。
- 专题综述的历史交接格式只有任务链接，故明确标为打开时的当前版本。未完成最终正文时显示已有章节，逐篇分析及依据按需读取，论文目录可搜索并分页。没有把这个链接宣称为冻结的历史版本。
- 没有行内引用标记的文档仍提供保存的论文依据列表。普通上传文本与图片沿用原预览方式。
- 桌面对话和 PDF 伴读共用组件。验收发现阅读器原本会先截获 Esc，导致上层预览和 PDF 同时退出；现在阅读器与抽屉共享最上层对话框的判断，Esc 交给当前窗口。

## 验证

隔离副本复用此前真实 FWI 回答、原样保存稿与人工修订稿；另用明确标记的合成任务覆盖版本和失败情形。所有服务商停用且凭据清空，禁止模型调用并记录尝试次数。

| 检查 | 结果 |
|---|---|
| 文档与选文 | 显示人工修订稿和准确选文；正文无内置读取指令，普通文本里的同名文字仍完整显示。 |
| 来源回查 | 无行内引用的 FWI 文档能展开当时的摘要；论文研究 v1 显示 v1 的旧片段；专题章节可按需读取逐篇分析与摘录。 |
| 版本 | 原样保存稿提示已有人工修订但保持原正文；研究任务最新为 v2 时仍打开 v1；不存在的 v99 显示错误和重试。 |
| 失败恢复 | 注入一次本机 HTTP 503 后重试成功，选文保留。 |
| 连续使用 | 从预览进入文档窗口，关联到当前对话，刷新后仍打开同一修订稿；新建对话未继承旧附件，可主动加入原稿。 |
| 窄窗口 | 430×780 下预览和页面宽度均为 430px，无横向溢出；正文可纵向阅读。 |
| PDF 伴读 | 合成单页 PDF 加载；从来源页码进入阅读器，伴读能关联并打开研究稿。Esc 依次关闭成果/文档窗口和阅读器，首次关闭保留 PDF。 |
| 自动检查 | 145 项前端测试、生产构建通过；新增测试覆盖引用解析、原始载荷不变、选文、历史版本及缺失版本。构建保留既有大 chunk 提示。 |
| 数据与调用 | 原有消息和导出文件对照不变；模型尝试 0，预览只读既有成果接口。 |

详细请求记录、隔离夹具和校验脚本位于本机 `F:/论文管理/artifact-preview-20260926/`，最终数据核对见 `validation.json`。开发验收中修改生产静态文件后按现有启动缓存机制重启了测试服务，未改运行时缓存策略。

这次验证的是成果能否被研究者看懂和继续使用，没有重新评估生成文本的科学正确性、千篇处理效果或真实人工用时。下一步应回到 FWI 连续任务的内容与修正成本验收；不能凭预览、测试数量或功能齐全宣称优于竞品。

# 持续研究的阅读与提问空间

2026-09-26。开发源码已完成界面与请求验证，尚未进入新的安装包；已交付的 0.6.13 保持不变。

## 用户任务与取舍

研究者沿着已有成果继续阅读、核对依据和追问，需要持续看见正文、材料范围及正在使用的模型。0.6.13 在 1280×720 窗口中常驻任务、技能、模型和额外复核控件，使正文只剩 229px 高。这里的主要问题是信息层级：每轮经常使用的是阅读和提问，配置通常只在切换研究方式时调整。

将配置收进“研究设置”，摘要保留当前任务与模型，主动选择的技能和额外复核也显示在摘要中。选择论文、关联成果、输入问题和发送仍沿用原流程，不新增阶段审批或输出限制。该改动服务于“查看成果 → 回查材料 → 调整问题 → 接续研究”，不增加新的研究页面。

## 先复用什么

- 项目已有原生 `details/summary`、论文材料组件、附件预览和本地草稿保存。桌面设置原先被强制展开，摘要又被 CSS 隐藏；直接复用并调整这些现有机制。
- [OpenCode TUI 官方文档](https://opencode.ai/docs/tui/)提供 `/models` 打开模型选择和 `/details` 切换执行细节的交互。借鉴其按需展开设置的方式，没有复制外部代码或增加依赖。
- 当前缺口是界面信息层级，不改变 Nature 的写作方法、检索策略或 agent 运行时。后续科研质量验收仍使用适用的内置科研技能。

## 实际行为

1. 桌面对话与 PDF 伴读共用默认折叠的研究设置，支持键盘展开。模型配置入口、任务、手动技能和额外复核控件保留。
2. 所选论文列表默认收起，摘要显示全文就绪数量、加载状态及不可用提示。展开后仍能重试和打开原文。
3. 附件使用紧凑预览入口；保存文档与研究任务标为“成果引用”，展开后说明可以读取该版本正文和来源。
4. 上下文压缩提示留在折叠区域外。保存错误、材料恢复和图片不兼容等现有状态仍可见。
5. 窄窗口允许摘要换行，控件与附件区可滚动；避免大量材料或展开配置占满全部正文空间。较矮侧栏展开设置后，输入区可能需要在控件区滚动到达。

实现仅涉及 [Chat](../frontend/src/pages/Chat.tsx)、[DiscussionPapers](../frontend/src/components/DiscussionPapers.tsx) 和 [样式](../frontend/src/index.css)。与 0.6.13 的 317 份程序及构建源码指纹比较，只有这 3 个文件变化；后端请求协议未改动。

前后对照分别使用 0.6.13 安装包提取程序和当前源码生产构建，均为隔离数据副本。几何测量使用同一对话、相同窗口与材料状态；源码副本在测试中新增了一条模拟回复，所测是正文区域尺寸，不是完全相同正文的阅读速度。

本轮模型请求仅发给 `127.0.0.1` 的确定性模拟服务，复制库中的原始服务商已停用且凭据已移除。共 4 次本机调用：一次长历史压缩及三次测试回复。模拟回复明确标记为界面验证，不作为科学结论；没有调用真实文本或向量 API。

## 交付边界与下一步

这轮减少配置对阅读的占用，未测量实际研究者的用时，也不能证明竞品优势。下一步沿 FWI 噪声、振幅及实际数据适应性的连续任务，核对比较条件、采用一次专业纠正并追问下一步研究，观察成果和来源是否继续沿用、人工核查是否省力。按完整任务验收，再将确认可用的改动纳入下一桌面候选版。

# 对话基本体验改进（2026-09-19）

## 本轮问题与结果

旧版只有文字输入框，图片能力是模型配置标记，没有图片或文件发送链路；工具运行前没有状态，停止主要中断前端连接，到轮次上限后只能重新执行。自定义模型明确设置的思考等级也可能被 LiteLLM 的模型目录静默丢弃。

现在支持以下实际操作：

- Ctrl+V 粘贴剪贴板图片、拖入文件、附件按钮多选；可预览、移除、仅发附件。最多四个附件，每个原始文件最多 10 MB。
- 图片归一化为 PNG，按多模态内容发送。PDF、DOCX、TXT、Markdown、CSV 及常见代码文件提取文字；文件内容可预览，每个最多 60000 字符，超过限制明确拒绝而不静默截断。扫描版 PDF 提示改用截图。PDF/DOCX 中的图表并不自动转换为图片。
- 附件保存在原消息请求中，刷新历史和重试都保留，不依赖临时文件。未发送附件在本次应用会话内按项目和对话分别缓存；退出应用后未发送附件不保证保留。
- 对话区直接选模型、编辑上下文窗口／思考等级／图片能力；选择仅影响本次对话调用，配置编辑沿用已有模型配置与共享连接同步规则。未知图片能力与明确不支持区分显示。
- 显式思考等级不会因自定义模型不在 LiteLLM 内置目录而被忽略；不支持的参数由服务商返回真实错误，用户可改回“自动”。
- 多模态内容兼容 Chat Completions、Anthropic 的 LiteLLM 入口和 Responses 输入转换；上下文估算不把图片 base64 当作普通文字。
- 生成时显示当前轮次、模型等待、正在执行的工具与核对阶段。停止通过后台取消标记，在下一次工具或模型调用前生效；无法撤回已执行工具，也不能保证立即中断服务商正在处理的请求。
- 达到工具轮次上限时保存消息、完整工具结果、证据与引用，点击“从已保存进度继续”恢复，不重复先前已完成的工具调用。此续接针对轮次上限；普通停止和网络错误仍显示重试。
- 工具卡片随最终回答持久化，重新打开对话可查看。上翻历史时不再被新状态强制滚回底部。

## 验证

- 回归覆盖图片规范化、文本编码、PDF/DOCX 提取、坏文件提示、图片内容到达模型边界、三种协议、多模态压缩、附件历史与重试、纯文本模型拦截、停止后不执行工具、轮次上限续接不重复工具。
- 独立 UI 数据目录 + 本地模拟模型的实际浏览器操作：Ctrl+V 图片、纯图片发送、Markdown 上传与预览、模型参数保存、图片模型切换提示、刷新历史、停止操作。
- 模拟模型确实收到图片内容块与文件提取文本，但这不等同于对每个外部视觉模型进行识图质量测试。未操作用户的微信客户端，微信特有剪贴板格式仍需 Windows 安装版实测。
- 本轮为源码改进，未覆盖已发布的稳定版 0.5.3 安装包。最终测试日志位于工作区 `chat-ux-20260919`。

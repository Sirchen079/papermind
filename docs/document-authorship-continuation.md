# 研究稿身份与后续接续

2026-09-27，0.6.19 后的源码迭代，尚未重新打包。

研究者要从此前的文献比较继续准备组会、检查证据或调整实验。前一轮 HV 核对稿已经保存了 `audit_author=Codex`、`adoption_status=not_user_adopted`，但前端忽略这两个字段，将其显示并传给模型为“人工修订稿”。默认文档目录还把明确尚未采用的草稿视为替代版本，隐藏其原稿。这使“谁改的、是否已经选择这份稿件”在交接过程中发生变化。

## 复用现有能力

检查了 `document_revisions` 的保存与上下文序列化、`saved_documents` 的目录与版本发现、成果附件、预览和对话文档卡。已有作者/采用元数据、明确的版本 ID、来源与输入文档关系足以承载需求；缺口是前端类型和展示未消费元数据，版本目录也未考虑已有的尚未采用标记。此次沿用现有存储和编辑流程，没有另建审批、版本系统或 Agent 运行时，也没有修改科研技能资源。

- 列表、详情、附件预览、对话保存卡和“加入当前对话”使用同一来源标注规则。明确记录的作者与采用状态优先于保存事件的消息角色；保留 AI 回答原样保存、AI 研究稿、人工修订和已采用建议的区别。
- 后续版本接口继续传递作者和采用元数据；描述不再把所有修订说成人工修订或独立分支。
- 明确尚未采用的草稿与此前版本均可找回，不将其自动视为替代版本。研究者实际编辑保存后，沿用既有版本关系收起被替代的祖先，原文仍可读取。同文件内容、不同状态的记录不会因文件名相同而互相挤掉。
- 阅读、讨论、选段核查和编辑均可继续，不增加强制确认或全局输出阻断。没有为历史资料猜测或批量补写采用状态。

## 真实界面与模型接续

验证目录：`D:/PaperMind-validation/document-authorship-20260927`。从上一轮含 1006 篇论文的资料库备份到隔离目录，保留研究稿、关联来源与配置；原始数据库和已有 69 条消息、24 个导出文件未改动。

从产品界面新建对话，搜索 `fwi-hv`：原稿 68 和核对稿 69 同时可见，后者标为“Codex 修订稿 · 尚未采用”。打开并加入对话，通过已有模型选择器使用 **GLM-5.3 / 智谱 Responses / `https://open.bigmodel.cn/api/v1`**，请求基于该稿整理约 400 字组会提纲。

实际发生 3 次文本模型调用，共 37,135 tokens；模型调用耗时相加为 53.48 秒，不含界面操作时间。没有向量和重排调用。模型读取准确的 69 号版本，说明它尚未采用，然后整理并保存提纲，没有要求先完成审批。新文件 `fwi-hv-group-meeting-outline.md` 为 AI 保存稿，关联输入仍指向原核对稿 69。

提纲保留了母稿的重要边界：频域噪声证据不能预先视为时域结论；带符号信号不等于增益不敏感；乳腺 USCT 不等于地震现场实测；新增 HV 一列为 10 次完整反演，原 30 次成为 40 次；仍需选择实验因素和资源取舍。它是对已有核对稿的提炼，**本轮没有重新读取论文原文**。保存文件末尾的“已核对 arXiv 版本页”等措辞应明确归属于母稿，不能当成本轮新核验的证据。原稿保留在交付中，未据这次单例声称科学质量或真实研究者工时优势。

桌面和 480×800 窄窗口均核对了成果预览的来源标注，刷新后保留，浏览器无控制台错误；模型实际收到的附件文字、保存文档 API 和输入文档关系亦已验证。156 项前端测试与生产构建通过，保留既有大分块提示。31 项不同的后端测试通过（26 项主回归、5 项版本/回答保存回归；其中新增状态链用例另补跑一次最终断言）。覆盖目录、未采用草稿、真实人工修订、历史恢复、不同研究分支和跨对话读取，详见交付测试日志。

此次没有新数据库迁移；此前的引用字段迁移随源码正常执行。当前修改须与前两轮元数据修复一起进入后续有意义的桌面交付。下一阶段继续以完整研究任务衡量找回、核查和复用的成本，不把身份标注正确本身当作竞争优势已成立。

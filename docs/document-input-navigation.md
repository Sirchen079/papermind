# 研究成果的关联文档回查

2026-09-27，开发源码实现。已交付的 0.6.16 安装包与源码包保持不变，本项尚未重新打包。

## 用户任务与现成方案

从实验记录表回到它依据的核对稿，再看论文原文，原本需要切换原对话、寻找输入附件。0.6.16 的真实 FWI 调用暴露了这个断点：输入核对稿保存了 15 项来源，新表只读旧稿正文，所以没有新增原文来源；文字页码仍在，直接回查入口却缺失。

本轮先检查已有 SavedDocuments、附件引用、生成要求、版本链、工具历史和来源展示。项目已能按消息编号和文件名读取准确版本，无需新增文档数据库或重建 agent。内置 Nature Paper Card 的 `references/evidence-and-provenance.md` 区分论文事实、分析、假设和用户判断；Nature Writing 的路由也要求保留证据边界。因此复用现成版本和阅读入口，单独保存或还原文档输入关系，不把读过研究稿等同于读过原论文。没有复制新的外部实现或修改原始技能资源。

## 行为与边界

- 文档详情与关联成果预览新增“关联研究文档”，可以打开原版本、查看其来源，再返回上一份文档。
- 关系取自实际保存的附件引用和工具记录。对于同一回答中保存的多份文件，只列该文件保存前的文档读取；后续读取不会倒算给先前成果。
- 新读取回执保留文档身份、读取范围和字数，避免历史工具结果的 800 字截断破坏 JSON。模型收到的完整内容不变。
- 用户关联、实际正文读取、来源片段读取、旧记录无法确认、修订前版本分别表达。这里只证明输入或访问关系，不宣称其中每个论断都被用于最终稿件。
- 人工修订沿用原稿输入关系，并提供直接父版本入口；保存回答也能沿原消息查到输入。关系按需读取，不递归展开全部旧稿和证据。
- 原文来源仍独立保存和回读；没有复制未读论文证据来充当当前成果的来源。旧目标删除后保留文件名并标为不可用，当前稿件仍可阅读和输出。
- 不增加模型调用、阶段审批或全局输出阻断；无需数据迁移，已有结构化引用的旧稿立即可回查。仅在自由文本中提及文档、没有明确引用或读取记录的情况，不猜测依赖关系。

## 验证记录

后端分两批检查：首次 39 项中 38 项通过，1 项新增测试因夹具缺少必填消息正文失败；补齐测试数据后，新增用例与工具历史、来源、技能回执相关测试共 27 项通过。两批共有 4 项交集，合计 62 个不同用例最终通过。覆盖普通与流式 agent 真实工具循环、长文读取回执、多文件保存顺序、跨对话修订与回读、仅来源读取、截断旧记录和目标删除。

前端现有 148 项测试及生产构建通过，保留既有大 chunk 提示。界面使用上一轮真实 FWI 资料的隔离副本，全部模型配置停用：从修订实验表打开准确核对稿，展开原文片段，再进入 PDF 第 14 页。另验证了文档内返回上一份准确版本、加入当前对话、从附件预览再次打开关联核对稿；浏览器错误日志为空。初次 PDF 打开因验收副本未复制 PDF 而失败，补齐副本和资料路径后重试成功；不是应用运行时修复。

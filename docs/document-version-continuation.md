# 让已纠正的研究稿进入后续工作

2026-09-26。下方保留开发阶段的验证记录；该功能随后纳入 [0.6.13 桌面候选](releases/release-0.6.13-validation.md)，原 0.6.12 交付不变。

## 产品问题

研究者在另一段对话里修正原稿后，回到旧对话、旧附件或旧文档入口时，仍会读取原稿。原先工具只返回指定内容，不告诉研究者和 agent 已存在后续修订。文档目录虽然默认隐藏旧版，旧入口却没有接到这条关系上，容易让已经纠正的问题再次进入讨论。

此次复用已有人工修订关系，为指定版本提供后续修订的入口。聊天中保存的文档增加“查看文档与修订”；打开旧稿即可看到后续稿并选择加入当前对话。agent 的 `read_saved_document` 同样收到可读取的修订记录。读取始终返回所指定的版本，历史对照仍可继续；不同修订分支分别列出，不自动混成一份定稿，不增加发送或写作审批。

## 现成机制与实现取舍

- 现有 `parent_filename`、人工修订消息、文档目录和材料附件已能承载关系，无需新建任务或文档工作区。新增修订补存 `parent_message_id`，以便区分恢复相同内容后复用同一文件名的不同记录；旧数据继续通过已有父文件关系读取，无需迁移正文。
- 参考 [Pi 的会话分支机制](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/sessions.md)：保留已有分支并明确选择继续位置。这里保留各条修订分支，不按保存时间擅自覆盖用户指定版本。没有复制上游代码。
- 核对内置 [Nature Writing 的修订工作流](../backend/builtin_skills/nature/nature-writing/static/core/workflow.md)：第 9 步强调局部修订、保留已正确内容以及在后续修订中保持一致。它提供修订方法；让已采用的稿件被后续任务发现，仍由应用保存关系和读取工具承担。本次未改写上游技能文件，也未为这一机制增加新的写作提示词流程。
- 后续版本查询只投影修订元数据，不加载全部稿件和工具过程。消息传输补充持久消息 ID，界面用它打开具体文档；不把前端临时消息编号误当数据库 ID。
- 修复恢复原始内容后的目录缺陷：原稿与恢复稿可能共用文件名，原先按文件名排除旧版本会连恢复稿一起隐藏。现在按保存记录和文件名区分，当前恢复稿仍可查找。版本时间显式标注 UTC，界面按用户本地时区显示。

## 验证

先新增四项回归：旧稿返回后续修订、跨对话分支、恢复原始内容、旧格式关系兼容。改动前四项失败，其中恢复稿不可见是已存在的缺陷。首轮实现后 31 项相关测试通过，一项新测试在关闭数据库会话后读取已释放对象 ID，修正测试写法后通过；原始失败日志保留。

最终 53 项相关后端测试通过，覆盖保存文档、局部采用、人工修订、对话传输及新版本关系。随后针对时间字段和持久消息 ID 补充断言，六项受影响测试通过（属于前述 53 项的子集）。141 项前端测试及生产构建通过，保留既有构建分块大小提示。

真实调用使用既有千篇测试库和 FWI 历史的隔离副本、用户配置的智谱 Responses、GLM-5.3。新对话只关联原稿记录 15，未直接指定修订稿记录 18，也未把修订内容复制到问题里。agent 读取原稿后查了一次本地书目，再沿版本信息读取记录 18，最终回答按人工修订说明振幅作为图空间坐标、区分预处理影响，并保留“不能推广为速度模型全局凸性”的限定。三次文本调用，24.23 秒，35949 tokens；没有向量调用。原始请求、工具结果、回答和审计保存在 `F:/论文管理/document-version-live-20260926`。

本例证明旧入口可引向人工修订，不能证明所有科研判断正确。模型没有重新核查原论文，并仍使用“稳健（凸）性质”等需谨慎理解的概括。回复共 348 字符，其中 223 个汉字，包含版本说明；未用额外截断强制篇幅。原始输出保留，未为通过验收改写。没有测量研究者总工作时间或竞品差距。

隔离界面验证使用关闭提供商的既有 FWI 副本：从原对话点击“查看文档与修订”，显示另一对话中的后续稿；打开后 §4 为已采用的修订内容；加入当前对话并刷新，仍关联修订文件。重启后核对修订时间显示为本地 17:34:09。默认桌面布局已目视检查；本轮没有重新做窄屏全流程验证。

## 保留的边界

没有明确继承关系的 AI 新文件仍独立保存，不能仅凭名称相似判断版本。跨对话关系依赖仍保留的修订记录；删除有关对话后不制造不可读取的入口。这个机制不会把旧稿所有相关段落自动同步改写，也不会强迫模型每次重读；需继续用真实科研任务检查修订是否被正确采用。

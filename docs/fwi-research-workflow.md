# FWI 真实科研任务：学术来源读取与超时恢复

2026-09-26。用户提供的真实任务是研究全波形反演目标函数，关注噪声、振幅和实际数据适应性。

## 已定位的问题

原始试跑使用真实 glm-5.3 Responses 接口，读取作者版 PDF 后，部分出版社网址返回 403。模型转向 Crossref/OpenAlex，却把原始 API JSON 当作普通正文多次翻页。OpenAlex 的摘要以词语位置索引存储，前面大量分类、作者机构和统计字段不帮助回答研究问题。复制的测试配置仍为每轮 12 次调用，最终在形成笔记前被截断；继续请求又在 180 秒后超时。不能把这些运行记为完成科研任务。

## 开发中的改动

- `read_webpage` 对 Crossref/OpenAlex 的 works 响应显示可读摘要、题名、DOI、作者、各类发表日期和原响应提供的论文入口。明确标识为元数据，不宣称读过论文全文。
- OpenAlex 摘要按词语位置还原；Crossref JATS 摘要转换为文本；检索结果中的不同候选论文保持分开。其他 API、未知结构与非 JSON 读取保持原样。`raw_json=true` 可读取未展示字段，切换视图从零偏移开始。
- 模型请求在已完成工具调用之后失败时，保留完整工具结果与消息上下文供继续。包含已经成功保存的文档回执；恢复不会自行重放保存操作。第一次请求就失败时，不宣称存在工具进度。
- 文档综述与 Agent 统一使用已有的按推理强度区分的生成等待策略：远程 medium 为 300 秒，high/xhigh/max 为 600 秒，普通请求维持 180 秒；较长生成与本地推理保留 10 秒连接超时，关闭自动重试。本地推理不设置读取时限。这修复的是路径不一致，不能保证服务商不再超时。

这些改动没有新增输出审核、强制证据门槛，也没有修改用户已有调用预算。已交付 0.6.11 安装包没有被替换。

## 已验证的范围

使用原始 FWI 试跑保存的 OpenAlex 响应回放：原始 JSON 为 16,900 字符，可读视图为 2,121 字符，223 词摘要逐词保留，保留 2 个原响应中的论文入口。这证明表示方式更紧凑，不证明论文质量或整体研究效率提高。

相关测试：学术/网页读取与研究工具 20 项通过；进度恢复、网页来源与来源历史 25 项通过；既有失败处理 6 项通过。测试包括候选论文分离、摘要还原、原始 JSON 可读、分页、来源快照、超时后的上下文恢复与文档保存不重复。出现一项既有 Starlette/AnyIO 弃用警告。

实际模型对照保留同一原始问题、同一模型及 12 次调用设置，使用隔离数据目录 `F:/论文管理/fwi-objective-readable-live-20260926`。结果和质量审阅应以该目录的最终运行记录及后续本文件补充为准。不能用单次成功证明所有研究主题或 1000 篇库综述已经达标。

## 实际对照与后续回放

可读来源对照完成 6 次模型响应，应用记录 133102 token，约 339.5 秒后第 7 次请求触及旧的 180 秒时限，未生成最终笔记。不能拿它与原始运行直接计算整体效率提升：模型轨迹、网络结果和终止位置不同。

该对照进程启动于恢复改动之前，所以失败时没有自动保留完整请求状态。后续在另一份隔离数据库中，使用测试记录的准确请求快照恢复，以验证后续生成，目录为 `F:/论文管理/fwi-objective-request-replay-20260926`。这是测试辅助恢复，不是产品自动恢复成功的证据；自动恢复与保存不重复由上面的 API 测试覆盖。

提供商等待策略另有 43 项相关测试通过（含两种协议、不同推理强度、远程及本地推理）。等待更久本身不算科研任务完成；仍需检查实际文档输出。

## 回放完成与内容核对

请求快照回放完成 3 次真实 glm-5.3 响应，共约 218.84 秒、115487 个应用记录 token。补读之后的写作请求耗时 184.66 秒，返回 `save_document`，保存了 11747 字符的笔记，随后正常结束。这一次超过了旧的 180 秒时限；模型采样和服务状态会变化，不能把单次差异完全归因于等待参数。

笔记具有可用的误差分类、源估计消融与文献入口，但内容仍有需要修订的地方：

- 将逐样本 Student-t 权重直接解释为整道降权；分组降权需要另行定义。
- 将归一化/包络对振幅信息的影响推广为 Q 基本不可反演，忽略参数还可能改变相位、频谱及单道内部形状。
- 将鲁棒、相关、OT/AWI 描述为正交问题，掩盖它们作用与失败机制的重叠。
- GSOT 的图空间幅值坐标与密度型 OT 的质量处理混在一起。
- 宣称三篇 SLIM 全文都读过，但 2012 年文章实际只读取 12000/14347 字符；有色噪声“空白”和预设方法排名也超出已读证据。

因此原始生成稿不标为科学质量通过。当前助手使用上一轮独立核对的材料重整了一份修订稿，通过产品的版本保存服务写入同一测试对话。修订注明 `revision_actor=codex_audit`，不冒充用户手写意见，也不伪造原 Agent 新增的全文读取记录。重新读取对话与下载均验证成功，原始草稿的字节哈希保持不变；此修订步骤没有再调用模型。

原稿：`fwi_objective_research.md`。修订：`fwi_objective_research-2e8c38f1.md`。验证记录：`F:/论文管理/fwi-objective-request-replay-20260926/audited-revision.json`。方便用户阅读的副本：`F:/论文管理/研究笔记/FWI目标函数-20260926/PaperMind核对修订稿.md`。

结论：来源表示、生成时间策略与失败恢复有明确改进，实际任务已形成可保存和修订的材料。仍未证明全自动综述达到可靠学术质量；下一阶段应继续以可核对、可修订的科研辅助流程验证，而不是增加一层全局拒绝输出规则。本轮没有重打安装包。

## Nature 技能是否真正生效

随后检查发现，上述 FWI 实战沿用了测试环境的 `PAPERMIND_NO_AUTOLOAD_SKILLS=1`，数据库没有技能条目，Agent 也没有调用内置技能加载工具。外围助手做文献调研时采用 Nature 指引，不等于产品里的 Agent 使用了 Nature Writing。原有专题综述路径会显式加载写作技能，普通对话原来仅提供三个技能工具的说明。这是两条不同执行路径。

优先复用现有内容：Nature Writing 的 stance/workflow 已规定缺项局部说明并继续写作、按证据强度表述、删除无依据的普遍判断、针对反馈局部修订；Review 分支要求按问题综合文献。Nature Paper Card 另有现成的事实/分析/假设来源规则。这些指导不等于正式审稿通过门槛，也不能修复网页 JSON 表示、超时或上下文容量等运行问题。

本次普通对话新增已启用内置技能的简短目录，继续使用原有加载器和资源；不预先注入全部技能。技能加载回执原先按一般工具结果截为 800 字符，资源列表和指纹常常丢失；现在模型仍收到完整内容，而对话回执保留完整 id、版本、资源列表、指纹与内容长度。33 项相关测试通过，覆盖普通/流式问答及已有技能行为。测试采用 128K 模型上下文；完整 Nature 写作指导仍可能超出默认未配置的 16K 容量，这不是小模型质量验收。

第一项真实验证位于 `F:/论文管理/fwi-nature-skills-live-20260926`：启用正常启动注册，使用先前保存的 8 段、6 篇原始来源快照，在新对话要求 1200–1800 字中文研究综述，不手动选择技能。模型完成 4 次 glm-5.3 响应，应用记录 111582 token、约 126.31 秒，并保存文档。然而实际轨迹只有检索、网页读取、保存，**没有技能加载**。因此目录改进不能宣称已解决自动路由。生成稿也仍把片段数混作论文数，把未读完的 2012 来源称为全文，并将概率密度式 OT 的归一化解释套在 GSOT 上；不标记科学质量通过。

下一项验证复用现有 `skill_ids` 显式选择接口，在相同来源快照与问题下加载 Nature Writing，目录为 `F:/论文管理/fwi-nature-selected-live-20260926`。不据单次生成差异宣称技能导致质量提升；分别核对实际加载、写作分支、来源表述、机制判断和成果保存。

该项已完成：3 次实际 glm-5.3 响应，应用记录 110993 token、201.94 秒。首次请求含 Nature Writing 核心，模型随后调用 `read_builtin_skill_resource` 读取完整 Review 分支，再保存 4803 字符稿件。没有等待用户批准；两次输入问题与材料文件哈希一致。两次合计 7 次模型响应、222575 token，不等于账单金额。实际文件内容与模型保存参数逐字核对一致，验证记录为 `F:/论文管理/fwi-nature-skill-validation-20260926.json`。

写作技能生效后仍有重要错误：把 2012 来源未读完的片段标为全文；将归一化直接推导为不应用于衰减或弹性参数反演；将 GSOT 振幅坐标与信号归一化质量混同；无定量依据地写“否则收益折半”。其中 GSOT 的原文 §2.3、式 (5)–(6) 明确以时间与振幅构成二维离散图，不能据此说它因概率化自动丢掉绝对振幅（[原论文](https://agupubs.onlinelibrary.wiley.com/doi/10.1029/2020JB021504)）。因此该稿同样未通过专业内容验收，保留原稿而不覆盖旧有核对修订稿。

补充资源阅读回执现在保存实际读取区间、全文与片段指纹，不再只保留不可解析的 JSON 前缀；新增范围核对与既有资源测试共 8 项通过。此项在本次实战进程启动后完成，实战 Review 内容加载以真实请求快照证明，不能把新回执格式倒称为本次已运行的行为。当前没有后台实战任务在运行，0.6.11 交付包保持原样。

## 任务入口与局部修订验证

开发版新增文献综合与修订综述入口，直接复用既有 Nature 阶段加载器。在 `F:/论文管理/fwi-workflow-revision-live-20260926` 用新对话读取上述已保存综述，选择 `workflow=review-revision`，未使用 `skill_ids`。首个真实请求包含对应资源、指纹和上游第 9 步的局部修改要求。问题由 Codex 提供明确的 GSOT 纠错方向，不能记作 Agent 自主发现错误。

真实服务为 `https://open.bigmodel.cn/api/v1/responses`，模型 glm-5.3，high 推理。10 次响应，共 217570 个应用记录 token，370.86 秒；这不是金额。执行链为读取已有文档、检索和网页补查、生成局部修改建议。Wiley 页面返回 403、HAL 大 PDF 超过当前读取上限；模型利用可访问摘要并区分外部核查建议，正常形成建议，没有增加全局拒绝输出环节。本轮未调用向量模型，也未重新检索或分析 1000 篇论文。

原始建议改正了核心的图空间表示混淆，但把幅值响应归于“质量赋值细节”，仍不够准确；还误称文末概括没有同类错误。Codex 通过独立网页读取补查原论文后，在现有建议编辑框中调整了第 4 节并采用新版本，正文注明这一贡献。具体说明保留了图空间坐标、逐道尺度与道权重、实测预处理之间的区别。整篇仍有其他问题，本次只验证指定章节的修订，不能标记整篇科学质量通过。

记录中的输入把公式位置写成了 §2.2，出版页实际为 §2.3。已更正文档说明，保留原始请求和响应，不改写历史。独立补查不算原 Agent 取得全文。

通过 Computer Use 验证：任务选择刷新恢复、切换对话各自保留、手动技能与任务模式切换；真实修改建议可编辑和采用；采用状态刷新后保留；新版本可从已保存文档加入当前对话。采用结果为 `fwi_nature_skill_review-259b20e0.md`、消息 18。程序核对指定章节以外文本逐字不变，全部原有导出文件哈希不变，新版本下载字节与文件一致，Windows 换行归一后与数据库正文一致；旧版仍可查询。测试导出文件在采用前从来源目录复制，作为隔离数据库的配套文件。

完整验证记录：`F:/论文管理/fwi-workflow-revision-live-20260926/adoption-validation.json`；单独的修订节：同目录 `codex-edited-section-4.md`。界面中的采用动作由 Codex 执行，属于隔离环境的流程测试，不是用户本人采用或人工省时实验。下一次真实模型是否正确沿用新稿尚未单独实测；本次验证到新版本成功加入后续对话材料。

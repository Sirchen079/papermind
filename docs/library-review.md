# 专题综述

## 使用

1. 在模型设置中配置对话模型。Responses 接口可使用 `https://open.bigmodel.cn/api/v1`，本次测试模型为 `glm-5.3-flash`。
2. 如需语义检索，添加 OpenAI 兼容连接 `https://api.siliconflow.cn/v1`，把 `BAAI/bge-m3` 设为向量模型。为论文建立索引；已经配置向量模型时，新导入论文沿用现有入库索引流程。
3. 导入 PDF 或已有书目，进入“研究”→“整理专题综述”。选择当前整个论文库或自选论文，最多 1000 篇，填写研究主题与比较维度。
4. 查看逐篇进度；可以暂停或关闭应用，重新打开后点击继续。没有全文的论文会使用摘要或已有摘录。
5. 正文中的 `[P编号]` 可打开本次采用的来源片段。可打开原论文、直接编辑正文、保存版本、下载 Markdown 和逐篇材料清单。
6. 添加新论文后更新综述。已有逐篇分析按主题、来源内容、模型配置复用；变化的材料重新分析，受影响的章节重新综合。旧版本始终保留。

未配置向量模型时仍可依据正文片段与关键词生成；语义索引可提高选材相关性。只有既无正文、摘要也无摘录的记录不能参与内容归纳。

如需由文本模型筛选检索候选，在“设置”中的“重排序方式”选择“大模型重排序（可共用文本 AI）”。默认不会自动开启；向量模型与文本模型分工不同。开发版已将专题综述改为先合并语义和关键词候选、再统一重排，相关真实调用与验证边界见 [检索验证记录](retrieval-validation.md)。

## 独立选择综述写作模型（0.6.5）

在“设置”→“专题综述写作”中选择模型，按项目自动保存；默认“跟随默认文本 AI”。逐篇分析仍使用默认文本模型，综合、论证规划、章节写作、整篇修订及按段 AI 修改使用所选写作模型。可以先完成整库分析，再比较不同写作模型，无需为相同论文重复支付逐篇分析成本。

更改写作模型或其思考等级后，下一次生成会重新综合与写作，未变化的逐篇分析继续复用；新增论文只补做新材料的分析。已运行的任务保留启动时的模型选择，要立即采用新设置，可暂停后继续。段落修改仍只返回预览，点击应用才保存为新版本。

模型的高思考等级可能需要较长时间才能返回正文。云端综述请求中，中等思考的读取等待为 300 秒，高及以上为 600 秒，连接等待为 10 秒；默认和低等级沿用 180 秒。本机模型继续允许较长推理。该设置改善请求可用性，不代表更高思考等级必然得到更准确的综述。

段落修改中，模型若明确报告输出额度耗尽，程序会扩大额度重试一次；仍未完整返回则提示并保留已收到的内容，可以继续手工编辑、应用或重新请求。整篇或分段修订未能补齐时，保留修订前正文，继续任务可重试该步骤。

本节功能由 0.6.5 提供。实测与限制见 [写作模型验证记录](review-writer-validation.md)。

## 查看生成中的章节（0.6.6）

“已保存的章节草稿”支持展开查看和下载，在更新已有综述时也可使用。首次生成默认展开；已有成稿时默认收起，成稿继续保留。章节内容随任务更新，尚未重写的章节可能沿用已有草稿；章节处理提示会一同显示、导出。最终修订可能调整这些草稿的结构和措辞。

0.6.6 同时保留已学到的模型输出额度，生成续跑及后续按段修改可复用，减少重复的空返回；没有增加单步重试次数，也不会自动应用段落修改。修订原文优先保留完整摘录和表格条件，小窗口放不下时明确标注节选。见 [验证记录](review-output-budget.md)。

## 已实现的处理方式

- 逐篇分析：每篇从摘要、摘录、跨全文选出的片段及语义命中中整理方法、评测条件、结果和局限。不是一次把所有全文塞入模型，也不宣称逐字精读每篇全文。
- 分层综合：每批最多 20 篇，进一步合并为全局主题梳理；根据主题拟定提纲，章节写作时再次检索原文。
- 本地检索：SQLite 原生向量距离排序，仅加载胜出的文本片段；无原生扩展时用流式排名。结合关键词与语义排名，并限制单篇占据过多片段。
- 可恢复执行：3 个并发逐篇请求，逐篇与逐章节提交数据库；暂停后忽略迟到结果。中断后手动继续，复用已完成步骤。
- 修改和引用：正文、来源快照和历史版本持久保存；每篇有完成、摘录回退或缺少材料的状态，可导出完整材料覆盖明细。

本版延续已有论文导入、PDF 提取和向量模型配置；没有新增云端向量数据库或独立部署要求。

开发版后续改动：普通 PDF 导入也保留实际页码，检索片段和综述来源沿用这些页码。来源旁的“查看 PDF 第 N 页”可直接打开内置阅读器，引用页优先于上次阅读位置。旧库已有全文不会被自动改写；需要补充页码时可使用已有 PDF → Markdown 转换。

## 输出与可靠性的平衡

没有“所有引用必须通过审核才能显示正文”的关卡，没有专题综述统一的 12 次调用或 600 秒总时限，没有强制 JSON 合格才能保存的要求。只保留使任务能正常运行的范围与资源限制：最多 1000 篇、有限并发、每次请求的上下文与超时。

- 单篇请求失败：重试一次，仍失败则用原文摘录参与综合，其他论文继续。
- 缺少全文：使用摘要或研究者已有摘录，并记录材料范围。
- 引用编号无效：局部标记“来源待补”，保留正文。
- 某章节失败：保留材料草稿，再次继续时重试；已完成章节不丢失。
- 格式不规范：接受普通正文、Markdown 或可读 JSON，不因格式丢弃输出。
- 模型或可读材料完全缺失：说明实际缺项，配置或补充后继续。

数字需同时保留数据集、指标名称、单位及比较条件，这是写作提示，不是输出拦截器。生成综述仍可能混淆数字或扩大结论；来源片段用于核对，不代表系统已经自动验证每一句话。精细表格、公式和跨页数据的理解也依赖原有 PDF/OCR 质量。

## 验证边界

- 1000 篇任务测试：使用模拟模型，逐篇均被处理、分层综合完成，所有论文进入覆盖清单，单次提示受上下文预算约束。
- 检索规模测试：1000 篇 × 每篇 50 段 × 1024 维，合成的 5 万向量，5 次查询中位约 0.302 秒，检验排序和论文范围过滤。该数字为本机数据库检索耗时，不包含网络向量生成或整篇综述时间。
- 真实接口测试：8 篇公开 arXiv 论文，使用真实 Responses 模型与 BGE-M3，验证全文解析、入库向量、引用和完整综述生成。详细结果在交付验收记录中。
- 1000 篇真实论文的完整综述质量和费用尚未做大规模评审。首次逐篇分析会产生相应模型费用，耗时随论文数量和服务响应增长。

## 产品方向

核心价值是让论文库成为持续更新的研究材料：既能基于全库形成研究路线，又能回到原文、修改综述，并在新增论文后继续更新。与基础文献管理或单篇 PDF 问答相比，差异主要来自整库覆盖、研究主题组织和增量复用的完整流程。后续应重点用真实研究课题评测材料覆盖和比较准确性，而不是继续堆叠拒绝输出的规则。


0.6.1 已接入完整内置技能库：写作阶段实际加载 Nature Writing 与 Oh My Paper，并保存论证简报和加载记录。详见 [内置技能说明](builtin-skills.md)。

开发版已增加按阶段选用原始技能段落、完整请求预算与长稿分章修订，实际验证与质量边界见 [本地 AI](local-ai.md)。这些改动由 0.6.3 安装包提供。

## 开发版：原文覆盖与写作预算改进

材料取样兼顾研究问题、方法机制、结果条件、讨论，以及可能改变结论的反例；默认优先正文，避免参考文献和附录取代主要方法。每个片段仍保留原始字符范围与已有页码。章节写作合并语义召回和逐篇原文快照，索引未完成或只有部分论文被索引时，也能选到不同论文的相关方法与结果。

真实论文复测发现，单纯按实验关键词选材会漏掉 RAG 的边缘化机制和 ColBERT 架构，也容易忽略 DPR 的 SQuAD 例外。当前取样已保留这些原文。中间分析和论证简报缩短，降低输出达到上限后将材料误判为缺失的风险；提纲解析排除章节列表前额外生成的总标题。

整篇修订的输出预算根据实际稿长计算，在上下文允许时统一删重、核对比较条件；超过容量时仍逐章修订。段落改写按选中文本长度预留输出，避免百万 token 上下文模型在改一段话时请求几十万输出 token。

原文取样吞吐测试处理 1000 次文档，耗时 15.678 秒，所有字符范围均能回到原文。输入是八篇真实公开论文的重复集合，无模型调用；这个测试不等于千篇不同论文的综述质量验收。

## 开发版：按段修改与恢复版本

综述正文下方新增“按段修改”。选择段落后，可直接编辑，也可填写修改要求让 AI 返回草稿。界面并排显示原段落与修改后内容；点击“应用这一段”才写入正文，并保存新版本。其他段落保持原样。草稿保存在本机，刷新后可以继续；未配置模型或调用失败不影响手工修改。

历史版本中可预览旧稿，点击“恢复为当前版本”将旧稿内容保存为新版本，中间版本继续保留。正文在其他操作中发生变化时，旧段落草稿会保留，需在新正文上重新选择位置后应用，避免覆盖研究者的更新。

已验证重复段落定位、中文及 emoji 字符、代码与公式块、只改目标段落、失败保留原文、项目隔离和历史恢复。浏览器实测刷新恢复草稿、模型缺失时保留修改、局部应用与恢复新版本，无页面异常和 390px 横向溢出。相关后端回归 34 项、前端 134 项通过。这些功能由 0.6.3 安装包提供。

2026-09-25 后续验证：包含原文取样、反例覆盖、整篇预算和段落输出预算的后端测试累计 42 项通过。八篇公开论文使用已配置云端 Responses 模型，18 次请求约 319 秒，完成六章写作与一次整篇修订，无请求失败回退；真实模型段落修改也验证了预览不自动保存、引用编号保留、只改目标文字和恢复新版本。压缩请求返回的段落仅略有缩短，说明改写质量仍需继续评测。

内容抽查确认 DPR 的 SQuAD 例外和 ColBERT 的 MaxSim 机制保留，但成稿仍将部分研究判断写得过强，例如将 RAG 的隐变量概率加权处理描述为检索结果被“无差别并入”，并从有限材料推导过大的领域缺口。当前结论是流程与来源覆盖改善，事实准确性尚未全面通过；后续优先评测这些机制归属和论断范围，而非增加阻断正文的规则。

### 按实际引用选择修订依据

后续改进让整篇修订和按段修改优先读取正文实际引用的论文，按论文轮流分配原文片段，覆盖方法、结果、例外与讨论。同一论文有多个独立实验章节时，避免只保留第一组实验及其消融。短章节标题与相邻正文共同取样，同时保留精确字符范围。只改修订提示时，可复用已经完成的分析和章节。

相关后端回归累计 48 项通过，包含千篇库中引用 P999/P800、4K/8K/32K 完整请求预算与末尾来源保留。第二轮八篇真实论文在 `glm-5.3-flash` 上约 313.7 秒完成，16 次模型调用、159212 tokens，两篇逐篇分析复用，没有失败回退。RAG 的概率边缘化机制表述已纠正，但仍存在过度概括、重复的比较限制及表格数字归属错误，不能作为内容质量全面通过的依据。

使用相同草稿、原文和提示另做两次修订调用：`glm-5.3-flash` 返回正文，`glm-5.3` 未返回最终文本，应用报告 `EmptyResponseError`。该结果不足以比较两个模型的写作质量；项目默认模型未改变。修订允许依据原文重新组织论证、合并重复章节，仍直接交付正文，不增加核查批准步骤。

针对重新组织论证的提示另做一次真实调用，约 76 秒完成，但仍沿用了错误的表格比较（把不同模型的 14.7 与 51.8 相减），也保留了部分过强结论。调整提示后，11 项上下文回归再次通过；内容质量未通过。下一项质量工作应把关键论断关联到对应实验结果、表格行列与周边原文，不能仅靠增加修订指令解决。

### 开发版：按论断补取全文和 PDF 版面

整篇修订、分章修订和单段改写现在会根据草稿实际引用，在对应论文中再次检索原文。数值采用完整数值匹配，并结合术语定位相关片段；涉及数字且存在本机 PDF 时，额外读取命中页按版面排列的文本，让表头、模型名与数值保持相邻。它是 PDF 文本的另一种排列视图，并非已经验证的结构化表格；扫描页仍依赖已有 OCR。没有 PDF、提取失败或无法命中时，保留原有证据与写作流程。

取回的材料优先分配修订上下文，同时为已有方法与结果片段留出空间。修订使用的原文和 PDF 页码保存在章节检查点，并显示在综述来源面板中；PDF 版面视图另存 PDF 内容哈希，普通全文片段保留字符范围。单段修改依旧只返回预览，不自动保存正文。

真实八篇论文复测取回 38 个定向来源，其中 14 个为 PDF 页，耗时约 1.52 秒，无新增模型调用用于此步检索。整篇模型修订约 44.3 秒完成，将错误的 14.7%→51.8% 改为对应基线约 14.7%→46%。但同一错误在单段改写中仍然保留，整篇稿也仍有过度概括，不能视作通用自动纠错已经可靠。此轮重点验证来源可达性和具体比较改善，未宣称千篇真实论文的内容质量通过。

本轮相关后端回归共 53 项通过，新增覆盖数值精确匹配、PDF 同行模型与数值、缺少 PDF 时回退、所引论文范围限制、修订证据预算与最终修订来源面板。该测试阶段未更改默认模型设置或项目许可；相关代码随后纳入 0.6.3。

# 本地 AI：使用与验收

更新日期：2026-09-25，版本 0.6.3。

## 产品定位澄清（2026-09-25）

用户明确的“纯本地”是指安装后直接运行、无需另行部署服务器。联网检索、文献获取、云端对话与向量 API 属于正常使用方式。本文记录的是可选的本地推理能力及其测试，不把断网或本地模型作为整款产品的使用门槛，也不以小型 CPU 模型的能力限制综述功能。后续首先验证真实论文上的检索覆盖和综述质量，允许使用已配置的云端模型。

## 应用内运行模型

设置页的“本地模型库”可导入单文件 GGUF 文本模型和向量模型。Windows 安装包携带 llama.cpp b11146 CPU 推理引擎，无需另行安装 Ollama、LM Studio 或 Python；模型权重由用户导入，不随安装包分发。

1. 准备模型的单个 `.gguf` 文件，在设置中选择文件、用途与运行上下文长度。
2. 导入后点“用于当前项目”。应用完成加载后保存该用途；加载失败会保留原有选择。
3. 导入文本模型和向量模型后，可以为论文建立语义索引、检索并进行带来源的问答。不同项目可以选择不同模型，但复用同一份权重文件。
4. “停止”释放模型进程，下次调用自动加载；退出应用时清理模型进程。Windows 下应用异常退出也会清理它启动的引擎进程。

导入会复制文件到应用数据目录的 `local_ai/weights`，以 SHA-256 去重。相同文件可以配置不同的用途或上下文；移除最后一个引用该文件的配置时才删除应用副本，原始导入文件不受影响。运行上下文与模型大小共同影响内存占用，请按模型和硬件能力填写。当前支持 CPU、单文件 GGUF；尚未提供 GPU 配置、分片模型组装或多模态投影文件导入。

“全部项目备份”包含模型目录与所引用的权重，恢复到其他位置后仍可自动加载。模型日志不进入备份。单项目备份不包含各项目共用的模型权重。导入较大模型后，完整备份也会相应增大。

## 连接已有本机服务

“连接本机 AI”仍提供 Ollama、LM Studio、llama.cpp 地址预设。检测服务后，将模型设为当前项目的文本或向量模型，并填写服务实际运行的上下文长度。

无需认证的本机服务可以不填密钥；需要认证的服务使用输入的密钥，并加密保存。连接失败不改变已有角色，重复连接复用已有记录。各项目配置独立。

本机服务地址不能单独证明离线推理：某些服务也可以代理云端模型。需要离线工作时，应选择本地权重，并检查翻译、OCR、重排序等独立用途的模型配置。应用不会因为导入本地模型而自动改动其他用途。

## 实测范围

- 真实 CPU 模型：Qwen3-0.6B-Q8_0（639,446,688 字节）和 nomic-embed-text-v1.5-Q4_K_M（84,106,624 字节），来自各模型官方仓库。
- 两个模型均通过应用设置界面导入并用于当前项目；桌面和 390px 窄屏检查通过，无页面异常或外部 HTTP 请求。
- 一份明确标为测试素材的文档生成两个向量片段，随后本地文本模型通过应用聊天接口生成回答并返回论文来源。
- 在该测试中，应用 Python 进程的非回环连接和外部 DNS 查询被禁用，已测索引与问答路径没有外网连接尝试。
- 强制结束应用测试进程后，它启动的两个真实推理进程均自动退出。进程清理另有真实 Windows 父进程异常退出测试。
- 模型管理、完整备份与恢复相关 34 项测试通过，包括共享权重去重、项目角色隔离、启动失败保留配置、备份迁移与停止加载。

小模型用于验证真实调用链路，不代表复杂综述质量。上述离线证据仅覆盖已测应用与浏览器路径；不是整个操作系统的网络审计。发行验收记录另行包含冻结桌面程序的启动、重启与随包引擎检查。

## 引擎、模型与接口来源

- [llama.cpp b11146](https://github.com/ggml-org/llama.cpp/releases/tag/b11146)：随包 CPU 引擎；MIT 与其第三方许可见 `third_party/llama_cpp/`。构建脚本校验下载包 SHA-256。
- [Qwen 官方 GGUF](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF)、[Nomic 官方 GGUF](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5-GGUF)：验收模型来源，权重不进入安装包或源码包。
- [Ollama OpenAI 兼容接口](https://docs.ollama.com/api/openai-compatibility)、[LM Studio 模型发现](https://lmstudio.ai/docs/developer/openai-compat/models)：已有本机服务的接入参考。

## 0.6.2 后续开发：小上下文综述

开发代码已将综述技能按阶段加载。原始 Nature 与 Oh My Paper 文件不变；模型请求使用当前阶段相关文件，在较小上下文中选取完整段落或规则条目，并记录来源文件哈希、实际摘录哈希、阶段与估计 token 数。不会把全部章节规范和路由清单重复放入每次请求。

预算覆盖系统指令、写作规范、材料和预留输出。论证简报、已有章节、论文分析及原文证据分别分配空间，避免后置的原文证据被简单尾截断。全文不能同时容纳输入和修订输出时，逐章、分段修订，保存中间结果并支持复用。模型失误或单步失败仍沿用已有内容，不新增整篇拒写门槛。

本地 CPU 的长综述调用不再使用固定 180 秒读取超时；连接失败仍及时报错。通过设置停止本地模型可中断引擎调用；暂停综述会保留已完成步骤，当前已经发出的请求可能继续到返回。

验证包括 4K/8K/32K 预算、末尾证据保留、原始技能指纹、无遗漏分段、逐章修订及复用、本机与远程请求超时行为。29 项相关测试和前端构建通过；界面无页面异常或 390px 横向溢出。

真实本地试验使用三篇 RAG、DPR、ColBERT 论文和 Qwen3-0.6B，8K 上下文完成逐篇分析、主题归纳、规划、六章写作和六章修订，没有请求失败回退。结果仍混淆检索与生成，跨论文综合弱且重复明显，因此只证明流程可运行，**没有通过内容质量验收**。已下载并校验官方 Qwen3-4B-Q4_K_M（SHA-256 `7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5`），同材料复测进行中。

本节记录 0.6.2 之后的验证过程；相关预算和修订改进由 0.6.3 提供，模型内容质量限制仍适用。

### 4B 阶段检查补充

4B 模型已完成三篇分析，但仍出现指标和任务边界错误。核查输入证据发现：现有检索词偏重 dataset、evaluation、experiment、baseline、limitation 和 appendix，RAG 的关键方法页及 ColBERT 的主要机制片段未进入候选材料。这是直接可复现的原文覆盖问题，不能仅靠增加模型规模解决。已保留 4B 分析与加载记录，停止该测试任务，下一步修复分章节的证据选取后重新评估；没有把这一轮视为综述质量通过。

# 多篇比较与人工修订工作流实测

2026-09-26，未发布源码。目标是检验 agent 是否能帮助研究者完成比较、改变关注点、修正并保存可继续使用的笔记。不是整篇自动综述评测，也未测量真实研究者的时间节省比例。

## 材料与步骤

使用真实千篇库的隔离副本，选择此前未参与本轮错误修复的三篇论文：P191 *Active Retrieval Augmented Generation*（FLARE），P245 *DRAGIN*，P174 *Small Models, Big Insights*（SlimPLM）。生成前先读取原文并固定方法、实现条件和来源核对点，保存在 `F:/论文管理/multi-paper-workflow-20260926/gold.json`；没有根据生成结果降低标准。

通过生产聊天 API 使用用户配置的智谱 Responses 服务、`glm-5.3`、low 思考及现有 BGE-M3 索引，连续执行：

1. 比较触发信号、触发粒度、查询构造、所需模型信息和训练要求，附论文编号及 PDF 页码，不跨论文排名实验分数。
2. 加入“目标模型只提供普通文本 API，不保证概率和 attention，不训练目标模型，但允许本地小模型”的原型条件，调整路线和实验。
3. 保存完整 Markdown 笔记。
4. 根据人工核查发现的矛盾追问：“你把 SlimPLM 称为唯一黑盒方案，但之前还列出了 FLAREinstruct”，要求回读、修订并保留旧版。

原型条件是测试题设，并非声称用户已确定产品必须采用这些论文的方法。第四步是人工介入，不能算作完全自主纠错；未开启额外证据复核，没有修改模型提示词来适配这三篇。

## 结果与尚需人工处理的内容

前三轮 90.74 秒，8 次对话调用，9 次全文读取请求及 1 次文档保存。新增记账 131690 tokens（chat 131419，embedding 271）。第四轮 48.67 秒、3 次对话调用、1 次全文读取、1 次保存，新增 75979 tokens（chat 75895，embedding 84）。总计约 139.41 秒、207669 tokens；不含人工核查时间，也不是账单金额。

两份原始生成文件都保留在测试目录 `exports` 中：`retrieval-control-comparison.md` 与 `retrieval-control-comparison-v2.md`。没有把人工修改过的文件冒充模型原始输出。

结论：完整协作过程能运行，研究者的一次针对性追问能纠正核心路线错误，但修订又引入未经请求的错误数值。此次没有达到无需修正即可采用的质量，也没有证明“大幅减少人工工作量”；可利用的比较骨架、原文入口和保存结果与剩余纠错负担都应计入评价。不要继续以多轮自动重试代替研究者实际采用情况的测量。

## 本轮修复：从修订稿回到早期原文

实际第四轮消息中，P245 本轮来源只有第 6 页等片段，第一轮读取的第 3–4 页方法原文仍保存在对话中，却无法从第四轮的来源抽屉找到。若用户核查新版笔记，必须重新翻到首轮回答找入口。

来源抽屉现在在顶部提供“此前读过的片段”，读取当前消息之前的同篇来源；当前已显示的完全相同片段去重，不同版本或位置分别保留。此前片段与本轮来源分开展示，不把历史材料伪装成本轮新增读取；点击早期页码即可打开 PDF。不会混入后续消息的来源，也不会因此增加模型上下文或 API 调用。这个入口同样适用于阶段稿和已保存成果的引用。

## 人工修订后继续研究

前述 SlimPLM 样本数错误暴露出另一个协作障碍：研究者已经知道正确答案，却只能下载文档或再要求模型改写。现已支持从对话中保存的 Markdown/TXT 成果直接打开编辑器、预览并保存新版本。原文件保留，未保存的草稿按工作区、对话和文件区分，在关闭、刷新及保存失败后保留。保存不调用模型，不增加批准流程。

人工保存增加一条明确标识为用户修订的记录，正文以用户材料进入后续上下文，不冒充论文原文或模型自发纠错。对失败轮次的缓存重试和待回答问题的继续执行，同样带入新修订，不因最新记录是手动保存而丢失原任务。保存与正在执行的聊天短暂互斥，以保持记录顺序；保存失败仍保留编辑内容。

使用上述真实对话、三份 PDF 和两份原始输出进行隔离界面验证，提供商关闭。手工按原文纠正 RJ/QR 样本来源和数量，并补齐可点击的 P174 引用格式。验证编辑、预览、关闭后刷新恢复、模拟 503 后重试、下载、再次编辑以及跳转 PDF 第 14 页；原文件逐字节不变。桌面和 390px 界面截图已查看，无横向溢出和浏览器异常。证据目录为 `F:/论文管理/document-edit-ui-20260926-v2`，人工版本为 `retrieval-control-comparison-v2-a7e29306.md`。

随后复制该已修订对话，重新启用用户配置的智谱 Responses 与硅基流动 BGE-M3 服务，只做一次真实接续：“按我刚才手动修订的版本，把 SlimPLM 两个训练组件的数据来源和样本量各写一行，不扩展其他内容。”使用 `glm-5.3`，没有改变针对这三篇论文的模型提示词。捕获请求确认完整修订文本确实以 user 角色传入；模型正确输出 RJ 从三个数据集各收集 5000、再过滤和降采样，以及 QR 从五个数据集各收集 1000、GPT-4 辅助标注，没有恢复成先前错误的“两个组件各 5000”。输出仍有少量未请求的引导和结语，并非严格只有两行。

该接续 HTTP 200，约 7.33 秒，1 次文本模型调用，无工具调用；新增记账 29053 tokens（chat 29017，embedding 36），不是账单金额。记录在 `F:/论文管理/document-edit-live-followup-20260926`。这证明了此例中人工修订可被实际模型沿用，不证明自动纠错能力、长对话成本已经合理，或研究者整体节省时间达到某一比例。

相关后端 86 项测试通过，覆盖保存、旧文件保留、重复请求、工作区/对话归属、磁盘失败、同步和流式接续、带缓存及不带缓存重试、待回答问题继续；前端 139 项测试和生产构建通过。本轮没有重新打包安装程序，新增功能仍在未发布源码中。

# Nature 精读卡脚本接入持续研究

2026-09-27。目标是减少研究者整理来源、检查精读卡结构和重新寻找检查结果的工作。承接[四篇 FWI 实战](fwi-four-paper-validation.md)暴露的缺口：原先产品能加载 Nature 资源，两个原始脚本却只能在外部验证环境执行。本次把它们接入现有论文、笔记、成果和对话，不另建研究入口。

## 复用依据与实现范围

- [OpenCode Skills](https://opencode.ai/docs/skills/)和 [Pi Skills](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/skills.md)采用技能发现、按需加载以及技能目录中的辅助脚本。它们解决技能组织与使用约定，不能直接承担本产品的论文身份、文档版本和桌面运行时适配。
- 查阅了 [Pi MIT 许可证](https://github.com/earendil-works/pi/blob/main/LICENSE)，本次没有复制其代码。Nature 沿用已有资源、许可与来源记录，原始脚本没有改写。
- 复用产品已有 subprocess worker、桌面 launcher、PDF 路径解析、保存文档读取、成果展示和整体备份。只新增 `prepare_paper_card_sources`、`audit_paper_card`、`read_skill_run` 的适配及执行记录下载。

支持的是内置 Nature paper-card 的 `prepare_paper.py` 和 `audit_paper_card.py`。不能据此声称全部 Nature 脚本已可执行。

## 使用流程和职责

Agent 可针对论文整理本地 PDF 来源，读取原文并形成精读卡，再检查已有笔记、精确文档版本或当前草稿。来源整理不会计作全文阅读；结构检查失败返回具体问题，研究仍可继续。研究者负责关键专业判断和最终采用，检查工具不改写原稿。

每次执行保存输入快照、原脚本 SHA-256、PDF 与卡片 SHA-256、退出码、日志和报告。未变化的 PDF 可复用来源整理；文件或脚本变化、缓存产物损坏会重新执行。Agent 可分页读回报告，用户可在原会话展开、下载并打开对应论文。报告默认折叠，避免占用正文阅读区域。

桌面程序以自身运行时启动原脚本，不要求用户另装 Python。完成的执行记录进入整体备份及恢复；本轮未扩展旧的单项目导出格式。备份不包含可重新生成的准备缓存或未完成执行。

## 真实模型与程序验证

测试资料在独立 profile，沿用此前真实 FWI 论文和核对稿。GLM-5.3 通过 Responses 接口实际完成 5 次调用，服务报告累计 74,844 tokens，45.11 秒；此前 49 条消息逐字段保持不变。没有新增向量调用，因为本轮任务是检查一份已定位精读卡。

模型首先整理 P1004 PDF、读取笔记，第一次审计多填了虚构 filename，与 note_id 冲突。工具返回精确输入提示后，模型自行改正并完成，没有新增审批或中断研究。此次没有独立调用 paper-card 技能路由读取；工作流有技能适配指导，且两个原始脚本的实际执行均有记录，分别陈述这些事实。

来源整理记录 `f2b7daef22694b9a9c6926439c7d3e37`：6 页，退出码 0，图、表、公式自动清单均为空，保留 warning。审计记录 `e90a32edbe184e08a1a983a6639b13cb`：14 项通过、0 错误，但报告继续呈现来源清单缺口。模型回答区分了结构通过与科学内容仍需核查。

PyInstaller 验证构建中的 EXE 实际启动了三个子进程：原始来源整理成功，核对稿审计退出码 0，旧稿审计退出码 1 并指出两项问题。没有依赖子进程外部 Python。此为内部验证构建，未制作新安装包，既有 0.6.16 交付不变。

源码服务加生产前端的界面验证：会话重新打开后报告仍在；下载报告 HTTP 200，文件哈希与记录一致；打开对应论文后阅读器载入正确的 6 页 PDF。展开操作以键盘验证，未据此宣称鼠标交互或完整桌面安装流程通过。

## 产品边界与下一步

自动图式清单为空时，覆盖率检查会出现“0 个全部覆盖”。产品保留这个来源缺口，不能把结构通过解释成完整阅读或科学正确。实际笔记中的图、公式、实验条件仍需原页核对；脚本也不能解决跨论文条件混用、研究结论过强等问题。

这一步减少手工运行脚本和搬运结果，尚未量化真实研究者节省的总时间，也未证明千篇综合质量或竞品效率优势。下一阶段应继续围绕同一研究任务，让关键判断、原文条件和修订稿之间更容易往返并保持关系；不要把补齐脚本适配变成继续扩张检查栅栏。

## 材料和实际执行

原始版本为 [Self-RAG 2310.11511v1](https://arxiv.org/pdf/2310.11511v1)、[CRAG 2401.15884v1](https://arxiv.org/pdf/2401.15884v1)、[RAFT 2403.10131v1](https://arxiv.org/pdf/2403.10131v1)，分别 30、13、11 页。54 页全部经过用户指定的硅基流动 DeepSeek-OCR，正文保存为本机 Markdown，308 个分块全部完成 BGE-M3 向量索引。实际新增 OCR 54 次、111440 tokens，向量 12 次、67399 tokens，导入分析调用为 0。OCR 完成后的记录脚本因字段名错误退出；从完成状态、实际用量和已发布文件恢复核对结果，没有再次识别这 54 页，准确端到端转换计时未恢复。

比较问题仅提供三篇论文、普通文本 API 与 BGE-M3、暂不训练但允许本机运行现成模型的条件，以及成果要求；未提供正确答案。核对标准在本轮模型调用前冻结。真实 GLM-5.3 high 执行后，保存 `rag-method-comparison.md`，读取 3 次目录、9 次正文并保留 9 个实际来源片段。每个片段均能在发布的 OCR Markdown 中找到，页码来自转换标记。此轮没有执行向量查询，不能用来证明三篇的检索召回率。

产品实际给模型加载 Nature Writing 的 related-work、review、stance、workflow 四份资源，并保留版本、资源和摘录指纹；不是只检查资源是否随包存在。加载规范不代表完成 Nature 的所有脚本，也不代表事实已核验。

## 原文核查与未解决的问题

选择的实验数字与原表核对：Self-RAG 的 7B PopQA 54.9/38.2/14.7（PDF 第 8 页）；CRAG 的 SelfRAG-LLaMA2-7b 分组 PopQA 40.3→59.3 与 54.9→61.8（第 7 页）；RAFT 的 PubMed 73.30/71.6/58.8、HotpotQA 35.28/4.41（第 5 页）。原稿区分 PubHealth 与 PubMed，没有直接用不同任务分数排名。没有将未选择的其他行或其他实验计为已核对通过。

原稿仍有实质问题：将三个完整方案的收益都归因于训练，超出了这些比较所能证明的因果范围；将 Self-RAG 原始训练流程写成用户必须重新训练，忽略允许使用现成权重的条件；Self-RAG 的 PopQA 检索设置漏写额外 5 篇网页文档（第 7 页）。反思 token 的类别和 RAFT 的 oracle/distractor 训练比例也未充分展开。局部复核没有自动解决这些问题，第一条原建议继续给出不充分的因果反例；第二条把 OCR 没看到与网页搜索为空当成缺少权重声明的依据。

第二处暴露了可修复的材料断点：Self-RAG 原 PDF 第 1 页脚注明确给出代码与训练模型入口，但这条脚注及 URL 在 OCR Markdown 中消失。原始项目页确有模型入口。不能将“未提取到”或“搜索为空”推导为作者没有发布。为此复用现有 PyMuPDF 的原始 PDF 超链接读取，新增通用 `get_paper_links` 工具；正文继续使用全页 OCR。链接、附近原页文本与实际读取的网页分开保留，详见 [原始资源链接](pdf-resource-links.md)。

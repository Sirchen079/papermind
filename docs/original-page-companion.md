# 将正在阅读的原页带入伴读

2026-10-08，开发源码功能验证完成，功能进入 0.6.29 本地候选构建。已交付的 0.6.28 安装包仍保留原样；最终打包与恢复范围见 [0.6.29 发布验证](releases/release-0.6.29-validation.md)，下文保留源码阶段的验证口径。

研究者核对实验表时，可以在 PDF 阅读器中点击“带入第 N 页原图”，随后沿用当前问题、已有材料和伴读会话提问。减少手动截图、存图和上传的操作；没有测量独立研究者的总工时节省。

## 复用与取舍

先检查既有 OCR 表格规范化、PyMuPDF、gmft 和 Docling。现有规范化已经能展开跨行跨列，无法补回识别时丢掉的主体、条件或脚注；新解析器在开发页也有合并条件、漏表等反例。参数固定的三篇新样本核查与原始失败保存在 `D:/PaperMind-validation/pdf-table-conditions-20261001/table-evidence-report.md` 和逐项审计文件中。20 项参考检查不代表整页或最终科研答案全部正确。

本项直接复用产品已有的 PyMuPDF、图片附件校验、IndexedDB 草稿和嵌入式伴读。没有添加机器学习依赖、数据库迁移或新研究页面，默认 OCR → Markdown → 索引流程继续使用原实现。解析器依赖只存在于隔离诊断环境。

## 使用行为

1. 当前 PDF 页完成渲染后可点击带入；读取的是点击时的物理页码，随后翻页不会改变正在读取的页。
2. 原页图片加入现有附件草稿，问题、已有附件、排队消息和研究任务选择保持原有内容。相同 PDF 指纹、页码和图片重复带入会去重；不同页或不同快照不会合并。本轮仍遵循现有四附件上限。
3. 展开附件可以看保存的图片，并打开当前 PDF 的相应页。标签明确区分保存快照和当前文件；当前文件后来变化，不会重新生成历史图片。
4. 带入只在本机读 PDF、渲染和保存草稿，不自动发送问题或调用模型。仅文本模型沿用既有图片能力提示和发送限制；问题与图片继续保留，用户可以选择支持图片的模型。
5. 页面读取或草稿存储失败时可重试。发送失败后重试沿用此前保存的图片及其指纹，不重新读取可能已经改变的 PDF。

后端沿用配置 PDF 根目录的路径边界，拒绝不可用、越界、损坏、加密文件与非法页码。记录 PDF 和最终图片的 SHA-256；渲染前后 PDF 指纹不同就返回可重试错误。图片沿用现有 PNG 格式、尺寸和大小校验。指纹用于快照一致性，不证明表格内容或科学判断正确。

前两次后端运行保留：新增测试数据漏填 `paper.source`，已修正并补用现有证据复核模拟；第三次运行有 45 项通过，一项因误写同步接口的超时错误状态码失败。现有接口返回 500，测试据此修正并单独补验。早期对等待原因的推测不是外部模型请求的证据；没有据此记录实际模型消耗。没有通过修改生产数据或降低校验要求使测试通过。

本轮没有评估真实视觉模型的表格理解质量，没有竞品同任务计时，也没有安装器升级验收。现有模型模拟证明图片传递与历史重试机制，不能据此宣称实验条件错误已解决。

# 精读卡到原文的直接回查

2026-09-27，开发源码。承接 Nature 脚本执行接入，检查“研究者阅读既有卡片、核对关键实验、继续思考”的实际路径。

## 断点与复用

论文笔记已有精读卡正文，但论文详情和 PDF 侧栏以纯文本显示 Markdown，表格不成表格；Nature 的 `[Paper: PDF p. 3, Equations 1–5]` 只能阅读，不能返回原页。原文虽在本地，研究者仍需记住页码并操作阅读器。

先检查既有笔记、Markdown、成果显示和 PDF 跳页代码，并查阅 Nature paper-card 的来源定位约定。[Zotero PDF Reader](https://www.zotero.org/support/pdf_reader)已有笔记回到原文的使用方式；它是应补齐的基本体验，不能单凭此项宣称优于竞品。[remark](https://github.com/remarkjs/remark/blob/main/packages/remark-parse/readme.md)支持解析后的语法树扩展，项目已依赖该技术栈。使用现有依赖的插件机制，无新依赖，无外部代码复制；本地 remark-parse 为 MIT 许可。

## 交付行为

- 论文详情和阅读器侧栏的笔记复用现有 Markdown 展示，保留标题、表格、列表和公式；编辑仍使用原始正文。
- 在有明确所属论文的笔记和对话保存成果中，Nature 的显式 PDF 页码成为链接。页码范围保留原文并打开起始页，提示中列出完整范围；同一指针含两处 PDF 页码时分别可点。
- 复用本地阅读器：在论文详情中打开指定页，在侧栏中直接跳页并保留卡片位置。既有 AI 伴读入口继续可用。
- 印刷页码、只有章节的标注、代码和已有网页链接保持原意；缺少论文身份的跨论文文档不猜测 `Paper` 指向哪篇。上游技能和保存的卡片正文未改写，没有额外模型调用或输出检查阶段。

## 验证

154 项前端测试与生产构建通过。新增测试覆盖真实 Markdown 解析、表格、单页、范围、多处页码、代码与链接、无身份文档和不完整指针。首次构建发现插件参数只读元组不符合依赖类型，改用依赖的公开插件类型后通过；没有修改依赖代码。

# 论文笔记的修订留存与接续

2026-09-27。研究者核对精读卡、修改研究判断后，应能查看旧判断、辨认变化并继续研究，而不必手工复制多份笔记。本轮补齐论文笔记的历史记录，沿用论文详情、原有编辑器和 Agent 的笔记读取工具。

## 已有方案与实际缺口

先核对 Nature Paper Card 的证据来源规则：区分论文报告、分析、假设和用户判断，并保留来源位置；这些规则用于本次产品设计参考，没有将版本测试宣称为新一次完整精读卡工作流。项目已有研究文档、综述和专题知识版本，也已有精确段落差异算法。缺口是 `patch_note` 直接覆盖笔记，既有 FWI 资料库的 `papernote` 表没有版本字段，Agent 无法再读取改前内容。

复用既有 SQLModel/Alembic、正文比较、Markdown 原文入口与研究空间复制。为笔记增加版本和独立快照表，旧库迁移保存当前内容为 v1；历史列表只读元数据，按需读取正文，避免打开阅读工作区就加载所有旧精读卡。新编辑不变时不增加版本。现有接口仍兼容不提供版本的旧客户端；当前编辑器发送开始编辑时的版本，避免另一处修改被无声覆盖。没有新增全局审批或模型输出检查。

## 使用流程

在论文详情的“笔记 & 摘录”中编辑并保存。存在修订后，展开“笔记历史”，选一个旧版本，优先查看其相对当前稿的实际增删；完整旧稿按需展开。“用此版本编辑”只载入原编辑框，保存后形成新版本，原稿与中间稿仍保留。分类、标签和原文位置一同保存。

Agent 的 `read_paper_notes` 默认读取当前笔记，也能按版本回读；长笔记的下一页指针固定版本，读取期间发生编辑不会拼接两个版本。来源快照同时记录实际版本和文字范围。跨项目复制笔记时复制其历史并改绑目标笔记身份，后续编辑互不影响；元数据导出包含历史，整体备份沿用完整数据库机制。

## 实测与取舍

在此前 1,004 篇库的隔离副本中，四份 FWI 笔记迁移后内容和原时间逐字保留。界面编辑 GCN 笔记形成 v2，从 v1 载入原编辑器并保存为 v3；中间 v2 未丢失，重启后仍能查看。v2 到 v3 恰有一段备注删除，界面直接显示该差异，不调用模型。

真实 GLM-5.3 high 使用既有智谱 Responses 配置，2 次调用、21,479 tokens、27.23 秒完成当前版与 v2 的比较。实际调用了两次笔记读取；保存的来源快照分别为 v3 的 650 字符与 v2 的 730 字符，均与各版本完整正文一致。笔记和历史未被模型改动。任务已给出论文与笔记身份，没有向量检索；本轮不以此宣称检索质量。

模型正确找到删除段落，但把“分别比较”推成“先噪声、后增益”的顺序，把“尚未采用”扩大为“从未采用”，还省略了时间的 UTC 标识。原回答保留，科研语义仅部分通过。相应产品处理是复用确定性的段落差异，减少为核对文字变化而依赖 AI 转述的需要，没有加入 FWI 专用禁令或额外审查调用。

截图检查还发现详情页的长标题与操作、提示语同排，压缩了正文空间；笔记与摘录分栏后又嵌套差异分栏，文字过窄。现已让标题、操作与提示分行，摘要按需展开，笔记和摘录纵向排列，差异按所在容器宽度排版。沿用现有配色、字体和组件样式。同一 1280×720 窗口，正文可用高度从 215.5px 增至 395px；390×844 窗口正文约 384px，无横向溢出，最终控制台无警告或错误。这是界面空间验证，不能换算为人工科研提效。

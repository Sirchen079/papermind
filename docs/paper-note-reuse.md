# 已保存论文笔记的完整回读

2026-09-27，开发源码，尚未纳入 0.6.15 安装包。

## 用户任务与实际缺口

研究者已让 AI 阅读并保存发现，或者在阅读器中修改了笔记。后续换一个对话做比较、选择实验路线时，应当能使用这些已有成果，并按其中的定位回查原文。

此前 `save_paper_note` 已使用现有 `PaperNote` 和阅读器接口持久保存，但 `search_research_notes` 只给 280 字片段，不给笔记 ID；`get_paper` 不展示已有笔记；Agent 没有读完整笔记的工具。因此即使已经保存成果，后续仍可能丢掉片段以外的实验条件和关键例外。

## 先核对的现成方案

- 现有 `PaperNote`、`reading.service`、阅读器编辑接口：已经解决保存、编辑、按论文归属和本地持久化，直接复用。
- 现有 `read_review`：已有按篇回读批量综述分析的路径，但材料属于指定综述任务，不能替代普通论文笔记。
- 现有来源快照和会话压缩：能保存已读材料和缩减模型输入，但不等于新对话能发现、完整读取一篇论文的最新笔记。
- 已安装 Nature Paper Card 的 router 和 `static/core/principles.md`：已有“主张对应证据、区分作者报告与分析、保留条件和定位”的组织方法。完整 16 节精读卡是独立任务，本次没有生成完整精读卡，也不宣称执行了其准备脚本或审计流程。

本次没有复制外部代码，也没有另建记忆数据库或强制逐篇审批。

## 接入已有流程

1. 沿用 `save_paper_note` 保存到原阅读器笔记，返回可回读定位。相同内容仍复用原记录。
2. `get_paper` 返回最多 20 条笔记目录与下一页位置；关键词搜索结果也带稳定笔记 ID 和读取参数。
3. `read_paper_notes` 可按论文列目录、按笔记读正文，用字符分页读完长笔记。不同对话共享同一项目的现有数据库，读取反映研究者的最新编辑。
4. 已读正文作为“研究记录”保留来源快照，带笔记 ID、更新时间和已读范围。目录本身不生成证据快照；笔记不被标为论文原文。需要核对论文主张时，沿用原文阅读工具。

这是让保存成果可再利用的基础能力，不保证模型一定主动保存、完整读取或正确理解。尚未把多篇综合的所有中间发现自动固化成笔记；后续是否加入任务级逐篇积累，应依据真实综合任务验收，避免给每个简单问答都增加写入和模型调用。

## 验证

36 项后端相关测试通过，覆盖跨会话存取、超过预览长度和 12,000 字分页的正文完整性、研究者编辑、目录分页、缺失/删除/不匹配论文和来源类型。前端生产构建通过；新增工具沿用原进度展示，显示“正在读取已保存的论文笔记”。

真实 API 验证记录：`F:/论文管理/paper-note-reuse-20260927`。采用千篇库的隔离副本和现有配置的 GLM 服务，第一个新对话读 CoN 并保存笔记，第二个全新对话读取笔记、回查关键原文、保存 API 实现选型建议。不给模型注入人工编写的正确结论；保留原始输入、输出、调用成本和失败。

- 18 次 GLM-5.3 调用、344,523 tokens，两轮分别 116.91 秒和 184.36 秒，无向量调用，无会话压缩。
- 19 次实际工具执行与模型提出的调用一致；一次保存笔记，一次保存建议。新对话经目录发现笔记，再完整读取 3,923 字正文，并回读论文。新进程和阅读器 API 都能取得同一笔记；文档下载与落盘字节一致；两份旧导出文件不变。
- 正确保留了 CoN 的 API 提示路线与训练路线的区别。但最终建议把全测试集误称为干净检索、把推理硬件当作训练硬件，并从提示试验无增益推出未经验证的机制解释。**科研内容未通过**，详见验证目录的 `audit.md`。
- 这次普通笔记流程没有实际加载 Nature 指导，不能宣称已执行 Nature 精读或写作工作流。后续科研验收需检查实际适用技能的执行证据。

本次只证明现有成果能够完整回用，不证明总体科研质量改善或用户工时下降。应回到 FWI 连续研究验收，检验已有核对和人工修改能否支撑后续实验选择，避免在同一篇验证论文上反复调整专项提示。

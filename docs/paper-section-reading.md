# 按章节读取科研原文

2026-09-26，0.6.10 之后的未发布源码。

## 问题与改动

[新主题实测](research-assistance-evaluation.md)中，模型将引言和短预览当作方法依据，误判普通文本 API 能否复现一项方法。单纯提高推理强度没有消除问题。本轮改进获取原文的方式，不增加逐句审核、强制确认或拒绝输出条件。

既有 `get_paper_full_text` 增加 `outline_only` 和 `section`。目录提供从提取原文识别出的标题、章节号、PDF 页码和字符位置；可以按唯一标题或章节号读取，包含下级章节、止于下一个同级标题。较长章节保留 `section` 并用 `next_start_char` 继续；`section_complete` 仅说明读到了识别出的章节边界，不证明整个论文或论证已经核实。

正文保留原始字符，不通过模型另写摘要。目录不生成来源证据；实际读取的正文继续进入原有摘录、页码、保存文档和历史来源链。页码、短语与偏移方式仍可用，目录缺失或歧义只返回可选位置，不阻止 agent 继续研究或回答。

目录是启发式文本解析，兼容 PDF 中章节号与标题分行、编号子章节、附录和 Markdown。已处理重复标题、表格列名、页码、早期选择题选项及正文编号列表干扰。未做 PDF 字体版面分析、扫描件 OCR 或人工标注的全库目录准确率评测，不能保证识别完整。

## 同一研究任务的真实调用

保持上一轮用户问题、初始千篇库和 GLM-5.3 high 配置，运行真实 Responses 调用。SDK 边界记录确认发送 `reasoning: {effort: high}`，未记录凭据。

这次选择 RAGHalu、Provenance、AlignScore，主动为三篇查看目录，再按章节读方法、实验、结果和成本资料。7 次模型调用、146.62 秒、150,385 tokens，保存了研究笔记。没有触发向量或重排调用。

正文编号列表使 Provenance 的第 3 节标题初次识别不准，虽然返回正文包含了正确方法。随后增加独立章节号优先的处理与回归用例；该修正在整库结构扫描和最终测试中验证，原始模型记录不覆盖。这次选文不同，不能把它当成之前 SELF-FAMILIARITY 误判已经解决的证据。

**本次整体产物仍不通过质量验收**：模型将文本 API 限制过度概括为“只能外部核查”，表格中没有清楚区分基线平均值的统计范围，仍给出缺少实测依据的执行费用和部署阈值。因此只确认章节入口被真实使用，未证明模型全面正确、成本降低或人工大幅提效。原始请求、响应、输出与核查在 `hallucination-research-sections-20260926`，不含凭据的 SDK 参数另有记录；测试数据库与语料不分发。

## 已知错误的专项回归

在最终解析代码上新建空白对话，只询问 #413 原方法在普通文本 API 条件下能否复现，未将正确答案交给 agent。这属于已知失败用例的专项回归，不是未见任务能力评测。

真实 GLM-5.3 high 先读目录，再读方法第 3 节、实验第 4 节和附录实现/成本部分。4 次模型调用、78.86 秒、48,738 tokens。回答正确指出需要 constrained beam search 和响应序列概率，援引 PDF 第 5 页方法与第 7 页 API-only 排除条件；同时说明换用另一个本地小模型会改变被测知识对象，属于待验证改造。关键适用性决定通过。

完整回答仍不记为全部通过：它又将若干 API 兼容基线称为“最强可用方案”，该排名并未由所读原文或覆盖全部候选的比较支持。原文读取能力与这次关键判断的成功，不能扩大为自动生成实验计划已经可靠。记录在 `paper-section-feasibility-live-20260926`，保留原始回答与专项核查。

# PDF 转换偶发失败排查（2026-09-25）

## 现象与结论

0.6.3 全量后端回归中，`test_document_jobs_and_model_settings_are_project_scoped` 曾返回 `error`，而非预期的 `ready`。当时整轮结果为 882 passed、1 skipped、1 failed；该测试单独重跑及文档测试模块重跑均通过。

保留下来的 PDF 可以正常提取原生文字。失败记录只有统一的 OCR 提示，未记录具体异常。**根因仍未确定，不能将后续通过解释为已修复这次偶发故障。**

本次在改动前启动按原收集顺序执行的前 240 项测试，并为后台转换线程记录异常类型及代码位置。240 项全部通过，耗时 372.81 秒；记录到的三次异常均来自既有故障注入测试，没有观察到额外异常。

## 本次开发版改动

- 区分读取记录、打开 PDF、渲染图像、提取文字、OCR、保存页面、发布全文和索引阶段的错误提示，避免将本地文件错误归因于模型。
- 日志记录论文编号、页码、阶段、异常类型和代码位置，不记录异常消息、局部变量、密钥或论文正文。
- 不改变生成或转换的接受条件，不增加输出审核或拦截。

文档模块 16 项测试通过（43.38 秒）。其中新增三种第二页故障注入，验证提示与失败阶段相符、旧全文和第一页保留、重试完成两页且没有重复发布页面。

这些改动尚未进入已交付的 0.6.3 安装包。若再次出现偶发故障，应先根据新日志定位实际异常，再做针对性修复。

## 0.6.4 复现与修复

后续全量回归再次出现同名失败。新错误分类将失败定位在发布全文阶段，数据库中第一页已经以 native 方式完成，尚未生成 `document.md`。测试项目中的页面路径为 251 字符，而用运行 UUID 命名的临时文件路径达 277 字符。

同一目录写入探测：250 字符文件可创建，278 字符文件抛出 `FileNotFoundError`。这说明本次失败由当前 Windows 环境的长路径限制触发；此前短目录独立重跑通过不能排除此问题。0.6.3 原失败未保留具体异常，因此不声称已经证明它与本次完全同因。

发布阶段已有进程内保存锁和运行标识检查，临时文件改为固定的 `draft.tmp`，短于最终的 `document.md`，继续原子替换，不会因临时名比最终名长而跨过路径限制。没有放宽覆盖检查或改变转换完成条件。该改动不承诺任意超长目录都可用：原 PDF、页面图片或最终文件本身超出系统限制的情况仍受环境约束。

文档模块 17 项通过（43.77 秒），包含新加的 245 字符目录用例：最终文件可容纳、旧 UUID 临时路径超过 260 字符时仍成功发布；并覆盖跨项目隔离、失败保留页面和旧正文、继续转换及导出。

首次完整回归最终为 917 passed、1 skipped、1 failed（1019.73 秒）。捕获日志明确为 `stage=publish type=FileNotFoundError`，栈位于临时文件 `write_text`，与路径探测一致。修复后的冻结桌面程序另在最终文件路径长 258 字符、旧临时路径会长 283 字符的目录完成原生 PDF 转换并保存完整正文。没有将这组定向复测表述为重新跑过一轮全量测试。

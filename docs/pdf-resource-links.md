# 从原始 PDF 查找代码、模型和数据入口

论文正文使用全页 OCR，但作者脚注的资源入口有时会漏掉。Agent 可调用 `get_paper_links(paper_id, page?, offset?, limit?)`，读取本机原始 PDF 的 HTTP(S) 超链接和可选择文本中的印刷网址。结果包含真实 PDF 页码、目标 URL、附近原页文本及分页位置，单次最多 40 条；继续时保持相同的页码范围。

链接本身只是资源入口。附近文本来自原 PDF，可以回到原页核对；只有后续实际执行 `read_webpage` 的网页正文才会保存为网页来源快照。没有可选择文本的链接仍可发现，但不能凭 URL 构造网页证据。扫描页、缺失 PDF、断行网址或空结果不证明作者未发布资源；网址存在也不证明目标当前可访问或权重适配用户任务。

复用项目已依赖的 [PyMuPDF Page.get_links](https://pymupdf.readthedocs.io/en/latest/page.html#Page.get_links)、既有库内 PDF 路径解析与网页阅读工具。无需新增 PDF 引擎、视觉模型或网络服务，不更改 OCR 正文、索引、笔记与已保存稿。PyMuPDF 既有许可证沿用项目第三方声明。

方案核对也参考了 [Pi 的 read 工具](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/tools/read.ts) 与 [OpenCode 的 read 工具](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/read.ts)。它们已有的图片/PDF 附件读取解决通用二进制传输，本次缺口是 OCR 漏掉的论文资源链接；仅参考工具边界，没有复制外部代码。

原始 PDF 实测发现 Self-RAG 第 1 页的代码和模型项目页、CRAG 第 1 页代码仓库、RAFT 第 1 页代码与演示仓库。读取未产生模型调用，测试数据库指纹不变。注释链接与印刷网址均可查，断行的印刷网址可能只是部分字符串，应优先核对 PDF 的完整超链接目标。可在对话中要求“检查选定论文作者提供的代码和权重入口，实际核对资源页并保存笔记”，由现有 Agent 接到原页和网页阅读流程。

同一材料的新对话只提供资源核查任务与使用条件，未提供 URL 或上一轮人工答案。真实 GLM-5.3 high 自行执行 3 次 PDF 链接读取、4 次网页读取、3 次论文补读及保存，在 155.20 秒、6 次文本调用、179325 tokens 后生成资源笔记。找到项目页中 Self-RAG 的权重与训练数据入口、CRAG 仓库中的 evaluator 权重和数据入口，以及 Gorilla 的 RAFT 子目录；未将 RAFT 读取页面没有下载链接泛化为“未发布”。原 PDF、OCR 文件、308 个向量分块和既有版本保持，没有新增 OCR、向量或导入分析调用。

核查范围仍有边界：没有打开权重文件、核对 checkpoint 身份、安装作者代码或实际试运行；原回答将参数规模直接推导为本机可运行，并将未查完权重的 RAFT 写成只能借鉴思想，措辞偏强。链接发现与网页读取通过，不能据此保证当前电脑复现成功或完整资源审计通过。原输出保留，未用人工核对稿替换为模型成功结果。

最终界面还发现，中文正文中的裸网址可能被 GFM 自动链接连同引号、中文括号及后文吞入错误目标。现复用既有 [unified](https://github.com/unifiedjs/unified)、remark 和 GFM 解析器，在呈现树中分开网址与相邻中文标点，继续解析同一段被吞掉的其他入口；显式 Markdown 链接（包括带中文标点的国际化路径）、编码网址、代码与原文存储保持。裸网址里的中文标点作为行文边界；网址本身包含这类字符时，使用显式 Markdown 链接即可保留指定目标。无需为某篇论文修改内容或提示，原始资源笔记直接得到可用链接。4 项新增呈现回归和完整 169 项前端测试通过。

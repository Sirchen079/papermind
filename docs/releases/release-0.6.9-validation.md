# 0.6.9 发布验证记录

2026-09-26。候选版本以科研协作为主要使用流程：AI 形成比较和笔记，研究者回查原文、编辑保存，后续研究沿用修订。实际时间节省比例尚未经过用户测量。

## 构建与桌面流程

前后端、Windows 文件版本及安装程序版本均为 0.6.9。前端 139 项测试通过，生产构建完成；保留既有超过 500 kB 分块提示。PyInstaller 与 Inno Setup 编译成功，安装程序约 402 MB。

首次候选构建在第二次桌面退出时捕获异步连接竞态，构建据此中止。修复只影响桌面专用事件循环，定序真实 socket 测试覆盖迟到连接关闭及正常往返，相关桌面测试 18 项通过。重新构建后连续两次真实 WebView2 启动、React 页面加载和正常退出均通过。原因及实现范围见 [退出竞态记录](../desktop-shutdown-race.md)。

在最终冻结程序上，用千篇库的隔离副本、三篇真实 PDF 和此前真实 API 对话验证：

- 保存成果与人工修订版刷新后仍可见，下载内容一致，旧文件字节不变。
- 编辑预览、关闭后草稿恢复、模拟 503 后保留修改和重试保存通过。
- 后续回答可回查历史 DRAGIN 方法原文并打开 PDF 第 3 页；人工修订保留 SlimPLM 第 14 页来源入口。
- 桌面与 390px 界面已检查，未发现横向溢出或浏览器异常。

此界面回放关闭了模型提供商，不冒充新的模型质量测试。原始模型调用、人工修订接续及输入成本对比见 [多篇协作实测](../multi-paper-workflow-validation.md)。最终冻结回放记录位于 `F:/论文管理/research-collaboration-frozen-069-v2`。

## 后端回归中的一次测试竞态

完整回归结果为 1022 通过、1 跳过、1 失败，耗时约 19 分钟。保留 Starlette 与 Pydantic 的两个既有依赖警告。

唯一失败为 `test_native_conversion_cached_and_portable_bundle` 期待索引状态 `unconfigured` 却读到 `pending`。测试辅助函数先通过 HTTP 读取快照，再检查后台运行标记；两步之间后台可以完成索引，造成辅助函数返回较早的 `pending` 快照。失败用例留下的数据库状态已经是 `ready/unconfigured`，独立复测也通过。问题出在测试判定完成的时序，并非 PDF 转换或索引任务没有完成。

修正辅助函数，使它同时等待快照内的索引状态结束；新增确定性的旧快照/新快照测试。随后复跑整个 PDF 转换模块及桌面相关模块，36 项通过，结果附在“修正后相关回归.log”。没有把原完整回归重写成全绿，也没有修改业务完成状态或放宽产品错误检查。

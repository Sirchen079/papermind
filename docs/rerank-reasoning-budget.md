# 共用模型的重排预算

百篇综述实测发现，GLM-5.3 high 被同时配置为写作和大模型重排。写作步骤按实际推理配置计算输出额度，重排却固定为 2,048 tokens、45 秒。因此仅需短 JSON 的任务仍可能把额度耗在推理中，正文被截断，再退回原召回顺序。问题不是向量检索突然变准，也不是模型成功重排。

实现前检查了本项目的模型用途选择、ProviderClient 的配置优先级、已有综述上下文预算及真实失败请求。复用已有 `response_budget`，将其提取至 `app/providers/output_budget.py`；综述继续使用相同计算，重排读取实际模型的推理强度并同时调整输入空间。高推理配置复用现有生成超时函数，普通配置保持原超时。没有添加新审批、额外检索服务或全局输出阻断。

真实单次重放保持模型、推理强度、问题、30 条候选和整个请求消息完全一致。额度由 2,048 变为 10,240 tokens，GLM 在 48.12 秒内返回完整的 12 个候选编号，总用量 12,681 tokens。编号均来自原候选且没有重复。它确认了传输和配置恢复，不等于排序相关性、科研结论或用户时间节省的全面验收。

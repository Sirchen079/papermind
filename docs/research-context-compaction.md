# 长研究对话中的纠正与成果接续

2026-09-27，源码修正；0.6.15 桌面候选未变。

## 产品问题与复用选择

连续研究中，较晚的纠正往往比最初草稿更重要。上一轮证明模型可能读到条件仍然理解错，本轮没有把那个语义问题归因于压缩；另行检查长期接续时，发现应用本身也会在摘要前丢掉纠正。

先核对了现有文档版本、人工采用和 `compact_history`，再查阅三种成熟做法：

- [Pi compaction](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/compaction.md)：接续摘要包含目标、约束、进展、决定和下一步，历史工具操作也参与序列化。本次复用摘要结构和工具操作区分的思路。
- [OpenCode rules](https://opencode.ai/docs/rules/)：项目规则可通过现有文件加载；适合长期项目约定，不宜直接把某一篇稿件的临时条件变成全项目规则。
- [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：压缩和持久笔记分别解决上下文容量与持续任务记录。当前已有可编辑文档和版本，本次先修复压缩，不另建重复笔记系统。

没有复制外部代码。Nature Reviewer 的适用范围是稿件同行评审，检查后未将其强行套到 agent 内部压缩，也没有启动多审稿人流程。

## 查明并修改的机制

旧摘要输入先截每条消息，再取合并结果的前 6000 个字符。较晚的纠正因此可能不进入模型；工具调用的 `tool_calls` 参数也不参与摘要。新增失败回归在修改前确实无法找到较晚的振幅条件纠正。

现在按 token 预算保留初始目标或上一份摘要、最近的用户要求，再从较新的历史记录回填。记录恢复时间顺序，跳过的记录和被裁短的长记录都有省略标记。工具调用包含名称、参数，工具回执包含对应调用编号和名称。它们只是供摘要阅读的历史数据，不重放操作；最近用户轮及活跃工具消息仍按原协议完整保留。

摘要指导改为按研究目标、用户约束、已采用决定、后续纠正、进展、成果入口和未决事项组织。明确区分助手建议、用户决定及成功操作，不要求补齐所有栏目才输出。摘要不是事实审查，也不保证模型遵循。

真实压力测试随后发现另一处旧行为：生成摘要稍长于剩余空间时，整份摘要被丢弃。现在把剩余预算写入摘要请求；仍超长时保留明确标记的部分摘要，避免一次成功调用后全部归零。最近原文不改，数据库对话不改；摘要失败仍按现有容错继续，不增加审批或全局输出阻断。

## 验证范围

回归覆盖较晚纠正、实际保存文件与回执、长工具读取序列、上一份摘要、中文预算、省略标记、超长摘要、近期问题及工具配对。第一轮 34 项相关测试通过；最后针对小预算和超长结果补充后，13 项上下文测试通过，另外 23 项对话与检索回归此前通过；这些测试分组存在重叠。

实测使用已保存的真实 FWI 模型输入，最终问题原样保留，主动将应用的压缩预算设为 21,000 tokens 触发边界。该值不是模型服务的实际最大上下文。测试只调用真实摘要与纯文本接续，不执行工具，不当作完整新对话的端到端验收。

首轮估算输入 18,927 tokens，压缩后 16,090，但生成摘要因超长被旧逻辑丢弃；最新问题和核对稿保留。两次 GLM-5.3 调用合计 20,741 tokens。失败输入、输出和记录保留在 `F:/论文管理/research-compaction-20260927`。修正预算处理后的单次重放记录在 `F:/论文管理/research-compaction-candidate-20260927`，最终结果以下附录为准。

这项修正减少的是应用造成的信息丢失；并未证明科学结论正确、模型必然沿用条件、人工时间下降或优于竞品。原 FWI 核对稿仍标记为未被研究者采用，不能把其中的条件性建议解释为已批准的实验决定。

## 修正后真实结果

第二次压力重放估算输入 18,927 → 16,999 tokens，在 17,000 的有效输入预算内。原始最新核对稿和本轮问题逐字保留，部分摘要带省略标记实际进入了下一次模型输入。对第一轮真实超长摘要做零调用回放，也确认从整份丢弃变为明确保留部分内容。

模型仍输出了超过请求预算的摘要，因此本轮验证的是部分摘要保留，不是无损总结。摘要还将旧助手解释重述为论文结论；后续回答保留了部分已纠正边界，但科研事实质量没有全面通过。第二次两调用共 23,140 tokens、86.36 秒；连同首轮，本轮实际为 4 次 GLM、43,881 tokens，0 次向量调用。没有速度、费用或人工提效改善的证据。

当前仍不能在单个极长的活跃用户轮内拆分压缩；摘要接口失败时也仍沿用原有保留近期记录的退化行为。长任务的这两类边界需继续按真实使用流程验证，不能把本轮检查扩大成长期科研记忆已完成。

后续源码补齐单个长用户轮的工具批次压缩，并在真实三篇阅读中完成保存；内容审计仍失败，准确结果与局限见 [多篇阅读中途接续](active-reading-compaction.md)。上段保留为此前验收时点记录。

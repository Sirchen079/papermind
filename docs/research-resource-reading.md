# 从论文追查可用研究资源

2026-09-26，未发布源码。接续上下文压缩研究任务：前两份模型笔记把论文中的训练步骤当作用户部署时必须重新训练，影响了方法选择。此轮检验从论文项目链接追查现成权重和推理说明的协作流程，不安装或运行这些研究模型。

## 发现并修复的工具问题

实际调用原有 `read_webpage` 读取作者 GitHub 仓库，正文为 9762 字符，返回的前 40 个链接被站点导航占满，没有作者的 Hugging Face 模型链接。原有工具虽能读到正文中的模型名称，却没有提供正文链接优先级或后续链接入口。

网页读取现在优先选取有实质正文的 article 或 main 区域；若 article 只是 main 中的小型相关文章卡片，则保留 main。正文链接先返回，其他页面链接仍保留并可通过 `next_link_offset` 翻页读取，每批 40 个去重 HTTP(S) 链接；文章外的文件标签页不会因此消失。无语义区域的网页继续使用整页，纯文本、PDF 和正文分页行为保留。表格单元格间加入分隔，避免相邻文本或数字粘连。搜索解析仍使用整页链接，不改变搜索结果提供商选择。

最终真实抓取：GitHub 作者说明为 6470 字符，首批包含模型入口；模型页面选取 main，返回 6563 字符，包含模型名称、BF16 与尚未填写的模型卡字段。曾发现直接优先 article 会误选模型站点中的 101 字符相关文章卡片，已在发布前修复并加入回归。内容选择属于静态 HTML 提取启发式，不承诺所有站点完整解析。

聊天指导同时区分“论文训练过程”和“使用已发布权重”；影响实际建议时沿作者链接补查，不增加强制确认、自动安装或输出拦截。

## 真实模型接续

从上一轮包含比较笔记的数据库复制隔离副本，继续同一对话。用户补充明确允许使用已发布权重，要求核查 CompAct 部署条件并保存补充笔记。没有将人工核查结论或模型 URL 注入模型上下文。

实际 GLM-5.3、low，共 6 次文本调用，44.56 秒，记账 61831 tokens；执行两次网页搜索、一次论文全文定位、一次作者仓库阅读和一次保存。Agent 从论文脚注找到项目，读作者 README 后，正确将“只能 prompt 复刻”修正为可试已发布的专用压缩器。保存 `evidence-compression-deployment.md`，原笔记保持不变。此次不涉及向量或重排调用。

作者[仓库说明](https://github.com/dmis-lab/CompAct)给出 `cwyoon99/CompAct-7b` 和加载后推理示例，支持无需重新训练即可尝试该权重的判断。[模型页面](https://huggingface.co/cwyoon99/CompAct-7b)由本轮开发核查另外读取；它仍有大量模板占位内容。**Agent 自己只读取了仓库，没有打开模型页**，不能将本轮开发者的核查计为 agent 的动作。

补充笔记仍有局限：15–16 GB 显存只是模型生成的粗略估算，不是完整工作负载测量；文本 API 接入是基于输出形态的工程判断，尚未执行集成；旧稿成本口径遗漏也被沿用。此轮证明关键训练/部署判断能经资源补查得到修正，不证明已在用户设备部署成功，也未测量人工节省比例。

另一个后续问题是网页原文尚未像论文摘录一样进入可长期回查的独立来源面板；当前模型请求中包含完整工具返回，保存笔记包含链接，但不应据此声称网页快照已获得同等的跨对话来源管理。

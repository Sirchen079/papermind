# 千篇库研究任务：阅读路线与研究者核查

2026-09-27。使用已交付 0.6.20 的新主题实测；本轮没有运行时代码变化。目标是确定下一项能减少科研工作的改动，不能把流程跑通当作科学质量或人工提效通过。

## 本轮完成与产品决定

在隔离的 1,006 篇旧库中指定三篇长文献问答论文，让真实 GLM-5.3 比较分块检索、长上下文及混合方法，生成可修改的中文路线笔记。Nature Writing 指导有实际加载收据；模型进行了 3 次目录与 8 次章节读取。95.23 秒、5 次调用、134,433 tokens 后保存原稿。指定材料无需重新向量召回，因此本次向量调用为 0，不能作为千篇库发现能力的证据。

独立核对原始 PDF 的表格与方法，发现漏报基线、正文与表格冲突未识别、把作者训练资源当作用户采用门槛，以及缺乏依据的实验阈值。完整方法阅读与 Nature 指导都不足以保证正确研究判断。保留原稿，另存 Codex 核对稿，标为尚未经研究者采用；准确出处随版本保留。

重启程序后在新会话关联准确版本，3 次真实调用、34,535 tokens、34.09 秒形成交接安排。它保留材料范围、比较条件、未知事项和草稿身份，交接通过。全部原有资料保留；未执行作者算法、未测人工工时、未证明综述质量全面通过。

**维持当前检索与章节阅读，先测同一候选材料上的阅读路线。** 总库管理、某个问题的候选论文选择、选中材料的深读分别评价，避免用“千篇可入库”推导每个问题的答案质量。研究者可以直接获得草稿、回查关键依据并局部修订；不新增逐阶段审批。

## 复用依据与边界

| 已有方案 | 本轮可借鉴的内容 | 仍需解决的部分 |
|---|---|---|
| 本项目的检索、章节读取、来源及版本 | 候选材料到局部修改、跨会话沿用已连通 | 内容核查成本和不同阅读范围的效果 |
| 已内置 Nature Writing | 按机制综合、限定证据范围、局部修订 | 不能代替核实具体表格和方法条件 |
| [Self-Route](https://aclanthology.org/2024.emnlp-industry.66/) | 先用检索上下文回答，不可答再扩大阅读 | 自判断的校准、中文科研迁移、成本；论文部分正文与表格数值不一致 |
| [Landmark Embedding](https://aclanthology.org/2024.acl-long.180/) | 专用表示可改善检索与上下文效率 | 普通 BGE-M3 API 不能直接代替；对应权重和推理实现未验证 |
| [Zhao 等 LongRAG](https://aclanthology.org/2024.emnlp-main.1259/) | 长段落映射、全局抽取、局部过滤 | 部分借鉴不等于完整复现；作者仓库代码许可尚未确认，不复制代码 |
| Ragas 官方 [Context Recall](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/) 与 [Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/) | 前者用参考信息检查检索遗漏，后者检查输出是否受已给上下文支持 | 参考标注与裁判也可能错；忠于有误原文不等于科学正确；本轮未运行 Ragas |

作者训练配置和使用者部署条件分开记录；未找到资源记为未核实，不写成不存在。未复制任何外部实现；本轮不调整本项目许可。

## 2026-09-27 第一轮比较设计（历史）

下述内容保留当时的设计。2026-09-30 已执行冻结协议；实际 C 为独立片段回答兼自判断，A/C 只共享检索结果，不复制 A 的答案。准确执行条件和结果见文末与[留出阅读比较](heldout-reading-validation.md)。

首轮规模采用 20 篇、40 问作为开发试点，不据此承诺全领域有效。问题分为单篇证据、跨篇综合，难度和篇幅分别报告。当前三篇和已见错误只进入开发诊断，不再充当独立留出效果证明；问题、参考材料与判定点冻结后再测试。若划分涉及同一篇或同一主题，应明确这种重叠，不能声称跨主题泛化。

- A：现有分块检索上下文后回答。
- B：同一候选论文的完整文本后回答。预算须包含系统提示、问题和输出空间；超窗记该条件不可运行，不静默截断。
- C：复用 A 的回答及可答判断，触发时改用 B。保留首次判断和完整成本，以参考证据检查错误自信与多余回退。
- D：LongRAG 的映射/抽取变体作为后续单独实验，不混入 A/B/C 首轮结论。

模型版本、提示中的任务目标、候选材料、输出预算和评价口径一致；记录路线自身引入的提示差异。若先做全库筛选，A/B/C 共用结果，得到的是筛选后条件比较。全库发现需另设参考论文集合，不能借此三路线结果证明。对同一问题进行配对比较，保留失败、超时和超窗，不只统计成功样本；开发阶段确定重复运行安排后，再冻结留出测试。

复用现有请求/工具/用量记录。每条样本留存 question_id、split、user_input、候选 paper_ids、PDF 哈希、实际送入的完整上下文及来源位置、response、reference 与 reference_contexts、路线和模型配置、请求时间、调用与重试、输入输出 tokens、缓存用量。Ragas 字段仅作为后续适配入口，当前没有自动评分结果；任何裁判配置与原始判定也需留存。

| 评价项目 | 判定方式 | 如何影响选择 |
|---|---|---|
| 关键事实与方法条件 | 逐项标 supported / contradicted / unresolved；原文互相矛盾另列，不强行选一个数字 | 错误基线、资源门槛和因果结论分别报告，不藏进平均分 |
| 证据遗漏 | 以冻结的必要参考证据检查已送入材料的覆盖；实际参考集合可能不完备 | 区分未检索到、未读到与读到后误解 |
| 回答证据支持 | 检查回答各主张是否能由给定材料支持，可借用 Faithfulness 辅助定位 | 不把一致性分数称为科学正确率 |
| 可继续使用程度 | 0：关键决定需重做；1：局部修正后可继续；2：按冻结清单核查后可直接进入下一步 | 保留具体修改，不将量表换算为论文 F1，不设未经验证的容许降幅 |
| 成本与主动工时 | 全链调用、token、索引及读取、等待、失败重试；研究者查证和修改另计主动工时 | 尚无账单价或真人记录时，不估算费用与提效比例 |

这张表是开发评价规则，不是产品的输出门禁。LLM 辅助评分可筛查分歧；最终科学判断回到原文与研究者。首轮展示质量、错误类型和成本的分布，再决定是否值得做自路由默认化。

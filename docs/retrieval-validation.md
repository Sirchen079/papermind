# 论文库检索与真实模型验证

2026-09-26，开发版；本页新增改动尚未进入已经交付的 0.6.6 安装包。

## 两阶段检索

向量模型负责生成查询与论文片段的向量，关键词检索补充直接用语命中。专题综述把两路原始候选合并、去除重复片段，再交给所配置的文本模型或专用重排模型判断与问题的相关性。最终采用模型顺序，不再经过第二次关键词融合。候选池限制同一论文最多三个片段，以免长文占满可供模型选择的位置。

此前程序对向量分支先重排，再融合关键词。这既使关键词独有的证据无法进入模型判断，也可能让融合覆盖模型顺序。开发版已修正；普通向量检索入口保留原有重排选项。

在“设置”的“重排序方式”选择“大模型重排序（可共用文本 AI）”，可跟随默认文本模型，也可独立指定。此选项按项目保存；没有自动改变用户原有设置。专用重排序模型沿用独立接口。关闭重排仍可生成综述。

重排超时或返回不可用编号时，保留已有候选。向量接口不可用时，专题综述仍可使用关键词候选及逐篇保存的原文。失败回退不等于大模型重排成功；验证时单独记录模型返回和排序是否实际采用。

这一步只对已经召回的候选排序。未进入候选池的关键原文，需要通过改写查询、拆解问题或补读原文寻找，不能靠重排补出。文本模型仍可能误判，排序分数只表示顺序，不是可信度。

关键词检索现在保留 `0.7` 等小数和 `1-PAGER`、`Recall@1` 等标识，避免拆分后丢掉比较条件。重排输入同时附带论文标题，便于区分来自不同论文的无标题表格片段。大窗口模型的候选总字符上限由 24000 调整为 60000，仍受配置上下文容量约束，每段最多 1800 字符；未知或小窗口的预算不随之扩大。这些修改不增加输出审批或正文拒绝条件。

## 实测记录

两轮对照使用同一百篇真实英文论文库、八条中文已知目标查询；模型为用户配置的 `glm-5.3-flash`，向量为 `BAAI/bge-m3`。每轮都在独立副本切换关闭/启用模式，原用户配置不变。

| 实验 | 关闭重排 Top-12 目标命中 | 启用重排 Top-12 目标命中 | 实际成功重排 | 重排报告 tokens |
|---|---|---|---|---|
| 旧顺序：向量重排后融合 | 8/8 | 8/8 | 8/8 | 48656 |
| 新顺序：两路融合后重排 | 8/8 | 8/8 | 8/8 | 45136 |

两轮关闭/启用 Top-1 均为 6/8、8/8，无失败回退。请求不是本地模拟；另一次产品 HTTP 观察确认 Responses 和 embeddings 实际返回 200，密钥与用户提供的完整值一致。平台账单未访问，报告 tokens 不能直接等同于扣费金额。

八条目标标签并不穷尽其他相关论文。这个小测试证明调用发生、已知目标可找回，不能说明整体检索精度、复杂主题召回完整性，或综述质量达标。新旧顺序这八题均命中，不能据此宣称新实现普遍更优。

原始实验位于工作区 `rerank-live-comparison-20260925`、`rerank-fused-comparison-20260926`，包含逐次请求、可见返回、实际采纳的排序、耗时及源码哈希。脱敏 API 核对在 `api-live-audit-20260925`。实验数据库不应进入分发包。

相关 64 项回归通过，覆盖两种重排后端、关键词独有候选、最终顺序、论文范围、长文占位和失败回退，以及既有检索、综述和跨页引用流程。初次测试命令含一个不存在的测试路径而未执行，改正后上述回归通过。

随后完整后端回归 966 项通过、1 项跳过（1070.28 秒），前端生产构建通过。不是把多轮重叠测试相加；本次全量覆盖包含上述修复。尚未据此生成新的交付安装包。

## 千篇检索暴露的条件缺失

1000 篇真实论文及 72912 个片段通过完整性审计后，在独立库副本上测试 16 个文献查找问题和 4 个实验条件问题。第一轮尚未包含上面的小数、标题和预算修复。16 个查找问题的 Top-1 从关闭重排时 11/16 变为开启时 14/16，Top-12 两种模式都是 14/16，但遗漏的目标并不完全相同。20 次 GLM 重排全部返回可用顺序，报告 128510 tokens。启用模式的候选上限为 30、关闭时为 20，因此此对照描述完整模式的效果，不把差异全归因于排序算法。

4 个条件问题在重排后全部把目标论文放在首位，但只有 GLEN 的目标片段同时包含预设数字与条件标记。1-PAGER 只返回介绍，缺少 31.7/34.2 对比；BERGEN 缺少 ELI5/WoW 条件；OneGen 缺少 0.7/2.0 对比。这直接说明“找对论文”不能作为“找到证据”的验收标准。

只修复关键词的小数与标识拆分后，第二轮在 1-PAGER 目标片段中找到了 31.7、34.2 及 top-1；OneGen 片段包含 0.7、2.0 和 Same Retriever，但仍缺跨片段的 TriviaQA 名称；BERGEN 的条件缺失未解决。16 个查找问题的启用模式 Top-12 为 15/16；此变化包含模型生成随机性，不能仅归因于词法修复。

另对第一轮的两个漏检目标及四个条件问题做真实模型查询翻译实验：仅给原始中文问题，让模型返回英文检索问题，不提供目标文献、答案或预设条件，再按原流程检索和重排。两个漏检目标均出现在首位，BERGEN 结果包含 ELI5/WoW；1-PAGER 与 OneGen 的数字条件仍未完整返回。该六题实验当时尚未接入产品，后续实现与验收见下一节。

数字标记检查只统计目标论文的原始片段，不把其他论文出现相同数字算作成功，也不把标记齐全算作回答事实正确。原始记录位于 `rerank-thousand-comparison-20260926`、`rerank-thousand-numeric-20260926`、`query-planning-probe-20260926`；均保留请求、返回和片段。后续需要保留相邻片段、扩大跨语言候选覆盖，并通过实际回答及全文写作验证条件是否被正确使用。

加入论文标题与大窗口片段预算后，第三轮使用原始 20 个中文问题复测：16 个查找问题的 Top-1/Top-12 为 15/16，唯一漏检目标为 RAGTruth；关闭模式仍为 11/16、14/16。20 次重排全部成功，报告 169696 tokens，含检索的启用模式总耗时 63.78 秒。实验条件仍只有 1-PAGER 与 GLEN 的预设标记齐全；OneGen 仍缺跨片段名称，BERGEN 仍缺具体任务。这是单次小样本结果，未隔离模型随机性，也不证明通用正确率为 15/16。记录在 `rerank-thousand-context-20260926`。

小数、标题与预算改动后的相关回归先有 36 项通过；随后扩大到检索、两种重排后端、千篇综述流程、引用依据与跨页处理，共 84 项通过（61.58 秒）。两轮有重叠，不相加。上述 966 项全量结果早于这三项新修改，不能代替其新版本全量验证。

## 中文查询补充与相邻原文读取

开发版在已选择“大模型重排序”的专题综述中，为中文问题调用同一文本模型生成一条英文检索问题。原问题保留，两种语言各自进行向量和关键词召回，合并后仍按原问题统一重排。关闭重排、专用重排及纯英文问题不增加翻译调用。翻译失败、空输出或截断时沿用原查询；不改变用户已有重排设置。设置页说明额外请求，模型用量以 `retrieval_query` 单独记录，查询改写沿用重排的 45 秒等待和无额外服务端重试。没有加入正文审核或拒绝输出阶段。

章节选材现在读取命中片段的前后各一个片段。只拼接同篇、同索引模型的相邻记录，元数据摘要不被当作前文；保存每个片段的原始文本和实际页码。命中原文排在上下文之前，避免小窗口裁剪时只剩前文。索引发生变化或相邻材料不可用时保留已有命中。来源抽屉展示涉及的各个实际页码按钮。上述变化不要求重建向量库。

同一千篇库上第四轮的 16 个已知文献问题，启用模式 Top-1/Top-12 均为 16/16，关闭模式为 12/16、14/16。原先漏检的 RAGTruth 已找到；提供给模型的翻译请求没有目标文献名称或答案提示。4 个条件问题在补读相邻片段后，预设标记均出现在目标论文的材料中，两种模式均如此。启用模式包含 20 次翻译和 20 次重排，重排全部采用，合计报告 186798 tokens，含召回总耗时 209.32 秒，16 个查找问题中位 8.25 秒。不同轮次的模型和接口返回有波动，不能把命中差异或耗时差异都归因于某一项代码修改，也不能把 16/16 当作通用准确率。

### 实际回答对照

再用同一 GLM 模型、同一回答提示，对四个条件问题分别提供第三轮和第四轮的原始检索材料，合计 8 次调用、68925 报告 tokens，全部完整返回。原回答保留，没有手改：

- BERGEN：旧材料回答缺少具体任务；新材料回答 ELI5/WoW，并把标注、长问题、评估和预训练等解释保留为待进一步研究的可能原因。
- OneGen：旧回答不知道 2.0 对应哪个数据集，并猜测多跳 QA；新回答正确给出固定 Contriever、改变生成器，以及 PopQA 0.7 / TriviaQA 2.0。
- GLEN：两轮都正确区分 2.3 个百分点与约 3.3% 相对提升；新回答遗漏了要求的 `[P48]` 引用标记，来源格式仍有问题。
- 1-PAGER：旧回答错误地称两者均使用 T5-Reader；新回答正文区分了直接解码与 Reader，但开头仍笼统称两者都“读取一个段落”，没有准确区分检索证据段落与读取全文，附加的 beam 说明也不够清楚。不能判为完全正确。

因此，本轮验证了两处材料缺失对回答的实际影响，尚未证明完整综述质量达标。原记录在 `rerank-thousand-expanded-20260926` 和 `retrieval-condition-answers-20260926`。

本轮检索、上下文与综述回归 84 项通过（62.27 秒）；补充的三种协议请求等待及用量测试所在文件 25 项通过，与前者重叠，不相加。前端生产构建通过。千篇副本的浏览器验收确认章节保存的跨页证据可回查，23/24 页按钮各显示一次，实际点击后 PDF 打开到第 24 页并呈现原页及文本层；千篇导出与窄屏仍正常。测试仅植入真实检索来源及已生成的问答用于检查展示，没有伪称通过界面生成了千篇综述。截图与结果在 `thousand-library-ui-context-20260926-v2`。

# 精读笔记如何进入批量综述

2026-09-27。本轮解决一处已经核对源码的协作断点：研究者在论文笔记中修改了条件或判断，继续批量综述时却仍复用旧分析。它会使人在阅读阶段的纠正无法进入后续综合，增加重复说明和核查的工作。

## 现成方案与缺口

先查阅 Nature Literature Pipeline 的 `references/review-compilation-workflow.md` 与 `references/note-template.md`，借鉴其盘点已有研究笔记、保留方法/批判/研究关联、再组织综述的流程。这是设计参考，没有运行该 skill 的每日检索、推送或归档流程，也没有把其中特定学科、受众或篇数示例变成产品规则。

项目已有论文笔记版本、综述逐篇缓存、材料快照和按段更新。本轮复用这些机制，不新建工作区或审核阶段。原 `paper_evidence` 通过 `collect_materials` 只读取论文正文、摘要与摘录；既不读取 PaperNote，也不把笔记变化计入分析指纹。由此可确定笔记修订不会触发原有综述分析更新。

## 当前实现

- 论文笔记以当前内容、编号和版本形成独立的研究记录快照。逐篇分析同时收到论文材料和笔记，明确区分两者；保存笔记不推断为研究者已经采用。
- 缓存包含实际笔记内容及版本。增加、修改或删除笔记，只使有关论文需要重新分析；没有笔记的论文保留原缓存身份，不为升级重算整库。
- 按段更新收到发生变化的笔记，即使模型简报没有复述纠正、当前段落尚未引用该论文，也能核对相关判断。章节写作及正文修订分别传入笔记与原文。
- 笔记不参与原文片段排名，不消耗原文选择名额。来源面板标明笔记版本，历史更新快照继续保留。只有笔记、没有摘要或正文的论文仍可整理研究记录，明确材料范围。
- 使用原段落编辑器请求 AI 修改时，读取被引用论文的当前笔记，不要求先重新运行整份综述。所有更新仍可保留旧稿和继续人工修改。

长笔记沿用现有上下文分配；保存完整快照，但不承诺每次小窗口请求都含完整笔记。按段更新为笔记单独分配空间，不增加额外模型审查或全局输出阻断。

## 验证

原始记录保存于 `D:/PaperMind-validation/review-notes-20260927`。自动回归覆盖笔记增删改的缓存失效、无变化接续、原文和研究记录的区分、仅笔记材料、小窗口以及单段修改读取新笔记。前端 154 项测试与生产构建通过。

真实模型验收使用此前 101 篇综述的隔离副本，只为 P105 添加一份标明 Codex 验收、非研究者采用的核对记录。GLM-5.3-flash 分析调用 1 次，GLM-5.3 写作调用 2 次，共 60,126 tokens、340.91 秒。两次向量接口包装层调用均命中原缓存、返回 0 tokens，没有新增向量用量记录；不能将其称为新的向量检索能力验收。

只有 P105 分析变化，其余 100 篇的指纹和分析逐字相同。三次文本模型实际请求均包含完整笔记和版本，笔记与论文原文分别组织。最终 4 处修改精确对应保存的替换，26 个原正文段落中 22 个逐字不变；修改快照中的笔记与输入完全一致。再次继续时，101 篇分析全部复用，正文、版本不变，新增写作调用为 0。原资料库哈希和 51 条既有消息不变。

科学质量仍仅部分通过：成本口径和风险措辞有所改善，但模型把“相对于同样训练改写器的方法”的限定推广为与 IRP、SeRTS 两条路线均无训练对象差别。核对库内 P20 原文可见其 Retriever 使用 DistilBERT 训练，与 RaFe 训练查询改写器不能据此一概而论。成本限定在两个段落重复，修改说明却各称只出现一次；说明还把 Codex 验收笔记称为研究者核对记录。另有“未检验”否定性表述需要更完整的原文核查。保留原输出和审计，不将流程接通当作百篇科学结论全部通过。

48 个去重后端用例的最终结果通过。保留两次测试失败记录：一项误以为删除笔记后仍存在可复用的旧分析缓存，另一项未为单段编辑入口配置测试模型替身；修正测试后定向复测通过，未修改产品行为迁就断言。154 项前端测试、最终生产构建通过。新进程实际界面能查看保存的笔记版本及分类；1280×720 与 390×844 检查可读，窄窗口无横向溢出，控制台无警告或错误。临时服务和页面已关闭。

本轮为源码改进，0.6.18 安装包保持不变。它解决的是已有纠正未进入输入的问题；科学判断正确、真实研究者总工作量降低和竞品优势仍需分别验证。

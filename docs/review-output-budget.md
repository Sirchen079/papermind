## 开发版处理

同一综述任务保存扩大的输出预留，后续阶段及重启续跑均可沿用。记录按模型连接、模型名、上下文和思考等级隔离，并发逐篇分析只会提高对应预留；新任务独立计算，不改变用户模型设置。扩大额度仍受上下文容量约束，每步最多两次调用，没有增加内容审核或批准流程。运行记录仅保存预算提示；历史任务没有该记录时仍正常开始。

增大输出预留会压缩输入空间，因此修订先给完整待修改正文分配空间，再将余量分配给背景与原文依据。整篇或分段修订的选择也考虑已扩大的预留。无法完整保留目标正文时保留已有全文，不用截短输入生成替换稿。更新修订缓存版本，已有逐篇分析继续复用。

进度显示增加综合分组和分层合并的批次，章节拟定单独显示阶段；进度条标注为论文材料整理，区分材料处理与后续写作。

更新已有综述时可展开查看并下载已保存的章节草稿，章节处理提示一同显示。草稿随生成更新，但可能含尚未重写的已有章节；原成稿始终独立保留。首次生成时草稿默认展开。提示和分隔线使用现有主题色，支持深浅主题。

修订原文检索按带引用的句子和分句分配论断，避免同一段中其他论文的数字参与当前论文的 PDF 页选择。相邻共同引用保留共享上下文，单一来源段落保持完整；同一句内部仅以逗号连接的多个引用仍共享句子，不宣称已经解决所有语义归属。这只是检索输入修正，不是引用正确性判定或写作关卡。

原文检索与已有来源快照补充论文标题，修订输入将标题、编号、摘录放在同一预算单元中。它让模型看到来源所属的研究主体；没有标题的旧版来源仍可读取，不据此拦截修订。

真实运行的第四章连续空返回后，旧逻辑把约 2.4 万字符的完整分析材料放入章节正文，使全篇超出一次修订的正文预算，转为六次分章修订。开发版仅对这一失败草稿使用正常章节的 3500 token 目标预算，仍均衡保留各篇材料；完整分析继续保存在逐篇检查点，失败标记和重试入口保留。正常模型正文不受此项缩短处理。

# 独立综述写作模型验证

2026-09-25 验证记录，对应 0.6.5。以下保留了开发过程中的原始实验，不能将局部修正等同于整库综述质量验收。

## 实现与验证

项目设置新增可选的综述写作模型。逐篇分析继续使用默认文本模型，后续综合、规划、章节写作、整篇修订和段落修改使用所选写作模型；未选择时保持原有行为。写作缓存包含模型、连接、上下文和思考等级，独立切换写作模型不会使逐篇分析缓存失效。

- 相关后端 69 项测试通过，覆盖综述、上下文、段落编辑、重排序及翻译设置；随后增强的 3 项写作模型测试通过，验证追加论文只补做新分析、改变写作思考等级只重做写作、项目隔离及修改预览不自动保存。
- 前端生产构建与 134 项测试通过。真实浏览器操作验证选择保存、刷新后恢复、切回默认，未发现页面异常。
- 后续请求等待调整的 68 项回归通过，包含上述部分测试以及模型接口和 Responses 协议测试。这些测试集有重叠，不相加作为独立用例总数。
- 未完成正文提示的后端验证中，首次运行 41 项通过、1 项失败；失败来自新增测试把“主动应用后版本应增为 2”误写为 1，已修正测试。随后段落编辑模块 9 项全部通过，验证部分正文只调用一次、附带提示、不自动保存，且仍可主动应用。

## 同一证据下的模型对照

从真实百篇测试库的第二版综述选择两个存在问题的段落，在数据库副本中调用实际段落修改入口。每次只返回预览，不写入原稿。两个模型都设置高思考等级，使用同一句通用修改要求，未将预期答案写入提示。

同一段落在两个模型上的消息内容 SHA-256 一致。原文已包含 BERGEN 的候选解释及 oracle 实验范围，不能把错误简单归因于没有提供对应材料。初始输出预算及自动扩大预算的规则一致；仅在明确的额度耗尽且无正文时重试一次。

| 段落 | 模型 | 耗时 | 结果 |
| --- | --- | ---: | --- |
| 检索收益与 oracle 范围 | glm-5.3 | 235.38 秒 | 第一次输出额度耗尽，扩大额度后返回正文 |
| 指标与引用归属 | glm-5.3 | 249.55 秒 | 第一次输出额度耗尽，扩大额度后返回正文 |
| 检索收益与 oracle 范围 | glm-5.3-flash | 180.16 秒 | 请求超时，无正文 |
| 指标与引用归属 | glm-5.3-flash | 356.08 秒 | 第一次额度耗尽，第二次请求超时，无正文 |

`glm-5.3` 返回的第一段将 oracle 条件限定为 ELI5/WoW，并恢复“候选解释、尚未单一归因”的区分；第二段将 BERGEN 的评价结论与 ATM 的 Subspan EM/F1 分开归属。但仍有偏强的跨设置概括，以及关于统一评价框架缺失的判断。因此这里只认可两个局部修正，不认定整段科学内容全面通过，也不能在另一模型没有正文时下质量排名结论。

该轮数据库记录了 5 次有用量返回的调用，共 97,216 个模型报告 token，包含额度耗尽的空响应。超时请求可能没有返回用量，故该数字不是全部服务端开销或已核实的计费金额。结果文件中每段的 `tokens` 只记录最后一次成功返回的调用，不能直接相加当作完整成本。

## 高思考请求的等待时间

上述超时暴露出普通 180 秒读取等待与高思考综述请求不匹配的问题。开发版将云端综述的中等思考读取等待调整为 300 秒，高及以上为 600 秒，连接等待为 10 秒；默认和低等级仍为 180 秒。本机模型仍允许较长推理，重排序等其他用途的等待时间不变，没有增加自动重试次数。

原始对照记录保持不变，延长等待后的单段复测单独记录。该修改只解决请求可用性，不承诺内容质量随等待时间提高。

延长等待后，`glm-5.3-flash` 对“检索收益与 oracle 范围”段落在 193.22 秒返回文字，只调用一次，没有触发扩大预算重试。消息哈希与原始对照一致，报告用量 22,409 token。该稿恢复了 oracle 条件和候选解释的限定，但以未写完的句子结束，也缺少原段落的第三组条件，仍未通过完整性和质量验收。这次实验说明超过 180 秒仍可能取得正文；前后请求不是可重复播放的服务端执行，不能据此保证每次都能成功。

随后给段落修改增加非阻断提示：Responses 明确报告 `incomplete` 或 Chat Completions 报告 `finish_reason=length` 时保留正文并提示未完整返回。不会只根据句末标点猜测截断，也不会自动丢弃已有输出或禁止应用；原稿仍须研究者主动应用才更新。该元数据提示是复测之后添加的，不能宣称上述真实请求已经通过新提示路径验收。

## 部分正文的恢复

0.6.5 将原有额度恢复扩展到非空残稿：只有接口明确报告输出额度耗尽时，才重新分配上下文并扩大额度，再请求一次完整改写。每个片段最多两次调用，其他未完成原因只保留内容并提示。二次请求失败或更短时保留已有残稿；二次请求正常完成则使用新稿。扩大额度导致无法完整保留选中正文时，也沿用此前收到的文字。

整篇修订和分段修订在仍无法取得完整回复时，保留修订前的正文，记录待重试状态；页面提示部分步骤未完成，正文仍可编辑和导出。再次继续只重试未完成的步骤，沿用已完成的逐篇分析。更新修订缓存版本让旧稿可采用新的恢复方式，不要求重做整库分析。

相关后端 66 项通过，覆盖补齐成功、补齐超时/空返回、第二次残稿更短、8K 分段和 32K 整篇修订、失败保留各章末尾内容、继续任务及分析复用。接口回归初次 43 项通过、3 项因新增兼容接口测试漏填 URL 而失败；修正测试配置后，该协议模块 13 项全部通过。上述测试集有重叠。

真实接口再次运行同一段落，消息哈希保持一致，`glm-5.3-flash` 高思考在 128.45 秒返回完整三组条件，接口报告 `output_incomplete=false`，单次用量 21,503 token，未保存原稿。本次文本将 oracle 限定在 ELI5/WoW，恢复候选解释的限定，并收窄翻译与问答的跨框架比较。此次没有触发恢复重试，不能声称新重试机制导致质量改善，也不能凭一段文字确认整篇综述准确。

## 0.6.5 冻结程序验证

最终 PyInstaller 程序连续两次通过原生桌面、WebView2、React 挂载及正常退出检查。使用独立数据目录和本机模拟模型接口，实际浏览器验证写作模型选择刷新后保留、请求使用该写作模型、截断回复从 600 扩大到 4696 输出额度后返回完整预览，以及预览不自动保存、手工补充后仅应用目标段落。浏览器未报告页面异常。

同一冻结程序中，第二次请求故意返回服务错误，仍收到第一轮部分正文及提示，数据库中的原稿保持不变。55 个技能入口可用，972 个原始资源哈希一致，本机 CPU 引擎可被发现。此项使用模拟模型，验证的是程序行为；未在用户现有安装位置执行升级或卸载。

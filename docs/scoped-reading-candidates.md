# 选定论文精读：候选截断修复与路线实测

2026-09-28。此项已进入开发源码，尚未打入新的安装包；已交付桌面基线仍为 0.6.20。

## 问题及改动

用户选中一篇论文，询问方法、实验结果和适用条件。原混合检索在大模型重排之前，固定每篇最多保留三个候选。真实请求中，重排模型只收到摘要和引言，后续结果表已经被程序丢弃。这不是提高模型推理强度能直接解决的问题。

修复复用现有融合召回、候选预算、大模型重排和相邻段落读取：明确选文范围内，按候选预算与去重后的论文数量分配每篇额度；单篇可以充分使用原有总候选预算。全库搜索的来源多样性规则不变，仍按用户所选模型执行重排，不新增全局输出阻断或阶段审批。

这项改动减少研究者为找回被提前截掉的表格而重复追问的必要性；是否减少总体核查工时尚未测量。它不保证召回包含所有必要证据，也不解决读到材料后误解训练条件等问题。

## 对照方法与复用

先检查 [Self-Route 原方法](https://aclanthology.org/2024.emnlp-industry.66/)、[LongBench 的评价实现](https://github.com/THUDM/LongBench/blob/main/LongBench/eval.py)和现有项目能力。LongBench 仓库为 MIT；本轮借鉴预测与评价分开的组织方式，没有复制上游代码。此前检查的 Ragas 指标只作评价定义参考，没有另建自动裁判。

新增开发脚本 `backend/scripts/compare_reading_routes.py`，复用产品 ProviderClient、混合召回、相邻片段、用量记录和 Nature Writing。参考答案不会进入模型请求；完整正文不静默截断。每次运行使用数据库独立副本，冻结数据与提示，保留失败和原始输出。脚本可选择 A/B/C 路线，重复运行须用新的输出目录。

- A：现有混合检索、重排和邻段材料后生成。
- B：相同候选论文的完整数据库正文后生成。
- C：独立执行 Self-Route 式可答判断，仅收到不可答标记时再调用全文。

三道题全部来自已见材料，是开发诊断；没有完成20篇40问的留出评测。每条件只运行一次。A/C 共用一次候选检索，比较各路线成本时各自计入；实际调用总数不重复计算。脚本固定材料后生成，没有完整 agent 的自主补读工具，不能将此对照等同于整个产品的质量排名。

## 结果及代价

原始对照的两个单篇问题，大模型重排分别只看到3个候选，均漏掉要核对的表格。修复后两题各看到30个候选，并实际选到结果表。Self-Route 数值题的回答补出了正确的表1数值；Landmark 题也写出正确表格，但触及本轮固定8192总输出token上限，保留为不完整回答。跨篇题重排看到29个候选，训练条件误判仍存在。

| 开发题 | 原 A 总 tokens | 原 B 全文总 tokens | 修复后 A 总 tokens | 修复后内容观察 |
|---|---:|---:|---:|---|
| Landmark 采用条件 | 8,663 | 21,038 | 29,684 | 表格可达，回答截断且仍有采用条件误判 |
| Self-Route 数值核对 | 11,704 | 22,592 | 27,770 | 正确列出表1数值，仍有适用条件概括过度 |
| 三方法 API 适配 | 20,897 | 65,340 | 25,584 | 训练与部署条件误判未解决 |

A 的数值包括查询改写、向量查询、重排与回答；B 不需要前述检索链。它们是不同模型的应用记录 tokens，不是账单金额。修复前后查询翻译和模型采样重新执行，缓存也会影响成本与延迟，不能用此小样本给出普遍效率提升比例。

原 C 三题均没有回退全文，其中两题明确承认关键表格未加载。持续交付任务、Nature 指导、路由提示遵循与模型自判断的影响未分离；据此不把自路由设为生产默认，也不宣称原论文方法普遍失效。

两轮共24次真实 GLM-5.3文本调用、12次 BGE-M3查询，合计261,075应用记录tokens。两份源库核验均未改变；没有重新索引整库。Nature Writing 1.5.0 指导在所有生成路线中实际加载，完整原始资源收据留存。

本轮固定8192输出额度与后续脚本默认值区分：发现截断后，脚本默认预算改为复用已有 `response_budget`，分别保留正文与推理额度；仍可显式指定8192重现本轮条件。没有据此重跑或替换失败输出，新预算默认尚未做外部模型实测。

## 验证和下一步

先构造“同一篇后续结果片段必须进入重排候选”的回归，旧实现实际失败。修复后52项相关回归通过；最终脚本预算等10项通过，与前者重叠9项，共53个不同测试。覆盖小范围候选预算、全库多样性、原/翻译查询融合、来源身份、跨页邻段、专用/LLM重排和失败回退。另修正一处旧测试替身，以接收产品已存在的推理参数，避免因签名不匹配而绕过目标断言。

完整记录在 `D:/PaperMind-validation/reading-routes-20260928`，可阅读交付在 `D:/PaperMind-deliveries/reading-routes-20260928`。该诊断轮未做新的桌面打包、UI验收或真人工时对照。随后0.6.21将修复纳入桌面候选，使用实际agent检索、补读和保存；见[0.6.21验证](release-0.6.21-validation.md)。这不替代原计划的留出评价及真人工时测量。

产品架构上的结论是分开评价全库找文献与选定材料的深读：少量材料中，查询改写和重排可能比一次全文更贵。下一步应在未见题目与完整交互任务中比较阅读范围，沿用现有来源回查和局部修订；不因本次三个例子新增固定篇数阈值、堆提示词或替换全局默认策略。

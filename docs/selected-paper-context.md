# 所选论文的完整正文进入研究对话

选择一篇或几篇论文比较、读方法或核对结果时，Agent 在首轮可能只有题录、摘要和研究记录，需要自己再找章节。2026-09-30 的20篇40问诊断发现，缺少应读条件是常见原因；已有自主全文工具没有总能补齐遗漏。开发源码现在会在现有上下文预算允许时，直接附入用户选定论文的完整入库正文，接入同一研究对话、来源回查和成果修订。

## 使用与预算

继续从论文库或研究对话选文并提问，不需要新入口、服务器或索引。正文使用现有入库内容，页标记和正文保持；新 PDF 仍沿全页 OCR 流程，旧资料不重做识别。自动供给不代表重新验证 OCR 或表格理解。

每篇正文作为整体尝试，预算同时考虑系统说明、历史、附件、工具定义、响应和来源沿用。能放入的保留完整正文；放不下的仍可用已有章节、PDF页码、位置与相邻片段工具阅读。上下文窗口以用户配置为准，估算不能认证提供方的实际最大容量。

已选摘录或精确保存稿的任务沿用其焦点。相同全文在后续对话中合并，变更后的正文版本分别保留；不同笔记、修订和网页资料仍可沿用。保存来源按位置保留全部正文，前端复用现有出处抽屉和原PDF页跳转。提供方明确拒绝工具协议而转普通回答时，不再为当前已经完整供给的论文额外付费检索；未供给的材料沿用原补读方式。

这减少的是反复找章节和传材料的往返；大输入可能增加用量和等待，不能保证比按需读取便宜、快或准确。

## 复用与代码范围

复用本项目的 `context`、全文导航、来源片段、历史来源、上下文快照及失败重试。没有新增模型依赖、迁移、论文专用提示或质量审批。预算与按位置继续阅读的设计参考 [Pi压缩说明](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/compaction.md) 和 [OpenCode读取工具](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/read.ts)，未复制外部代码。

实现新增 `backend/app/agent/selected_materials.py`，调用点在已有对话构建。相同正文合并使用正文哈希检查，旧快照保持不变；新来源保留论文、位置、页码和供给消息身份。

## 实际证据与限制

新增9项、连同关联回归共111项通过，覆盖两个消息接口、超预算全文延后、高响应预算、失败重试、修订接续、摘录焦点、不同正文版本共存及工具拒绝回退。不是全后端重新通过声明，前端实现未变。

用此前40题未使用的 RepoCoder 与 SciAgent 做一次真实 Agent 对照：相同1006篇库副本、问题、glm-5.3/high和配置窗口，旧0.6.26源码先跑、新源码后跑。六个源文单元在调用前冻结，模型未收到参考答案。新版首次输入原样提供181905字符正文，原版随后8次全文工具补读；文本调用为5→2。

本次耗时56.55→92.28秒、总tokens110671→132372，增19.6%；有提供方缓存报告且固定顺序，不能作为公平现金费用对照。必要单元完整支持5/6→6/6，但两版均把ChatGPT带工具条件的30.9混成不带工具的31.0；新版另有正确主对照，所以必答单元通过不代表整篇正确。核对未盲化执行，没有独立研究者、人工工时或统计质量结论。

实际界面回查完整正文、打开SciAgent第7/36页Table2、另存修订并保留16段来源和父版本。隔离库缺少受管PDF导致首次打不开，补齐副本并核对哈希后成功，无OCR或嵌入。修订由自动化操作完成，不表示研究者采用，不加入原始模型成绩。

原始报告和15份筛选证据在本机 `D:/PaperMind-deliveries/selected-reading-20260930`。20篇40问的冻结报告保持原样，新例不混入旧评价。[0.6.27验证范围](releases/release-0.6.27-validation.md)另记录打包证据；科研质量、独立人工净节省与竞品优势仍需验证。
